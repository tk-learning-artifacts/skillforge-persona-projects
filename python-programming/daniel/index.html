Lost in the Lab

A Python text adventure about binary. You stayed late and the school is locked. Every door has a keypad that shows a binary number. Type it in denary to get out.

I'm Daniel. I've been a trainer for six months. I teach a Sec 2 coding enrichment class on Wednesday afternoons. I'm learning Python alongside them. Last month we did binary with paper cards. So I built a game where binary opens every door.

This is my end project for the Python module. It has the game, a PRIMM worksheet and a lesson plan. It also has the bugs I hit, because there were a lot of them.

How the code works

The whole game is 102 lines. Open "Read and change the code" above to follow along.

  • Four rooms, four functions. corridor(), store(), lab() and server() each print the room, then return the name of the next room.
  • The main loop is at the bottom: while room != "outside":. Each time round it calls the right room and adds 1 to moves.
  • A list for the items. items starts empty. The store adds "torch". The lab adds "card". The server room checks "torch" in items.
  • A dictionary for the doors. codes links each door to its binary code. keypad("lab") looks up codes["lab"], which is "0110".
  • A for loop for the binary. to_denary("1101") gives 13. place starts at the value of the left bit, 8 here. It halves on every pass. Each "1" adds its place to the total.
  • A while loop for typos. ask() keeps asking until the player types a real exit. It also answers items and card. So a typo never crashes the game.

The doors use 4 bits, then 4 bits, then 8 bits. The last one is the hard one, and the card is there for it.

My share link

The brief asks for a share link to the working program. This part took me longest, so here is what I found.

  • I looked for a Share button in the Raspberry Pi Code Editor. There isn't one for your own projects. In July 2023 the Raspberry Pi Foundation decided not to add code sharing. It said that without moderation, sharing is a safeguarding risk.
  • You can use the Code Editor without an account. The same post says your changes last for the session. They survive a refresh or a closed tab. To save your code properly, you log in.
  • Under 13, a parent or guardian sets up the account with their email. From 13, you can sign up alone (Code Club). My Sec 2s are 13 or 14. But my school prefers no student accounts, so we don't log in.
  • The school version is called Code Classroom. There, a teacher can copy a direct link to a class or project. Students then sign in with a school code, username and password (help page). My school hasn't set it up yet.

So my share link is this page. Anyone can open it and play. To run the game in the real Code Editor:

  1. Pick adventure.py above, open "Read and change the code" and press Copy code. Or press Download .py.
  2. Open the Code Editor and start a new Python project.
  3. Delete what is there, paste the game in and press Run.

Bug diary: what broke while I wrote it

I kept a note of every error. These six cost me the most time. The messages are exactly what Python 3.13 printed. Older versions word some of them differently.

TypeError: can only concatenate str (not "int") to str

I wrote print("You escaped in " + moves + " moves."). moves is a number, and + can't join text to a number.

Fix: commas. print("You escaped in", moves, "moves.") adds the spaces for me too.

Hint for students: "str" means text and "int" means a whole number. Which one is the number?

NameError: name 'item' is not defined. Did you mean: 'items'?

I typed item.append("torch"). The list is called items.

Hint for students: Python is guessing for you. Check the spelling where you made the variable.

UnboundLocalError: cannot access local variable 'moves' where it is not associated with a value

I put moves = moves + 1 inside corridor(). Inside a function, giving a name a value makes a new local variable. This one had no value yet. The Python FAQ explains why.

Fix: I count moves in the main loop instead. global moves would also work. I'd rather my class didn't need it yet.

Hint for students: count things in the main loop, not inside the room functions.

SyntaxError: expected ':'

I wrote if choice == "lab" and forgot the colon.

Hint for students: lines starting with if, elif, else, while, for and def all end in a colon.

IndentationError: expected an indented block after 'if' statement on line 59

In store(), I forgot to move items.append("torch") in under the if.

Hint for students: after a colon, the next line moves in 4 spaces. The error points at the line after the problem.

(no error at all)

The worst bug had no message. The keypad asked again and again, even when I typed the right number. I had written while guess != answer:. Then I added print(type(guess), type(answer)). It printed <class 'str'> <class 'int'>. input() always gives back text, says the Python docs. So "6" never equals 6.

Fix: compare text with text: str(answer). This bug became question I2 on my worksheet.

Hint for students: if nothing errors but nothing works, print the type of each value.

PRIMM starter and worksheet

The starter is a 22-line slice of the game: one door, one keypad. It keeps to_denary(), a while loop and a list of wrong guesses. The worksheet has 3 Predict, 3 Investigate, 2 Modify and 1 Make question. It prints on one A4 page. My answers for teachers are on the same page, under the sheet.

I only learned about PRIMM in this module. It stands for Predict, Run, Investigate, Modify, Make. It was developed by Sue Sentance and colleagues (Raspberry Pi Foundation). The first three stages are all about reading code. I used to start lessons with a blank screen.

The lesson plan

The lesson plan is one 60-minute lesson for my 28 Sec 2 students. They work in pairs on school Chromebooks. Its timings add up. It has a plan for slow typists and typos. It also shows how I check that every student codes.

Rubric check

  • Program runs without errors. I played four routes through the game in Python 3.13 and on this page. Each one ends with "You are outside". A typo can't crash it, because ask() just asks again. A wrong code only beeps.
  • Uses functions, loops and a list or dictionary. Seven functions. A while loop in the main program and in ask(). A for loop in to_denary(). A list, items, and a dictionary, codes.
  • Worksheet questions make students read code. All three Predict questions come before anyone runs it. I1 is a trace table of to_denary(). I2 asks what breaks before they try it.
  • Plan fits your students and devices: nearly. It fits 60 minutes, 28 students in pairs and their Chromebooks, with no logins. But school devices run device management apps, and some sites get blocked. I must test the Code Editor on a student Chromebook before the lesson. This page is my backup.

What I would change

  • The server door asks for 1101 every time, even when the room is dark. Players hated typing it twice. A list of opened doors would fix that.
  • to_denary() trusts its input. A code like "1201" would count the 2 as a 0. A stronger student could add a check.
  • There is no saving. Close the tab and you start again.
  • I stopped at "the Code Editor has no share link". I haven't tried Code Classroom yet. That's my next step, and I'll ask our ICT team about school accounts first.
