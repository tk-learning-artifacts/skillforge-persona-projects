One locked door

A 60-minute PRIMM lesson for Sec 2 beginners. Students read a 22-line Python program before they change it. It ends with the full game.

  • Class: my Wednesday coding enrichment class. 28 Sec 2 students, in 14 pairs.
  • What they know: print, variables, input and if, from 3 lessons on Python. Binary place values, from paper cards last month.
  • Time: one 60-minute lesson in the computer lab.
  • Devices: every secondary student has a school PLD. Ours are Chromebooks. One Chromebook per pair is open. The other stays shut for notes.
  • Tool: the Raspberry Pi Code Editor, with no logins.
  • Printouts: one worksheet per student. A mini whiteboard and marker per pair. One error hint card per pair (below).
  • On the board: the short link to the worksheet page, so nobody types the starter.

Before the lesson

  • Open the Code Editor on a student Chromebook, at school, on the school network. PLDs run device management apps, and sites can be blocked. If it's blocked, ask the ICT team a week ahead.
  • Paste the starter, run it, and type 4 then 6. Check the output matches P3.
  • Print the worksheets and hint cards. Set a timer to ring at minutes 23 and 43 for driver swaps.

By the end, students can

  • Predict what a short program prints before they run it.
  • Trace a for loop in a table, one row per pass.
  • Explain why text from input() needs str() or int() before a comparison.
  • Change a program so a while loop stops after 3 tries.

Success criteria, in student words

  1. I wrote my predictions before I ran the code.
  2. My trace table gives 6 for "0110".
  3. I can say why "6" and 6 are different.
  4. My door locks after 3 wrong tries.

The lesson, minute by minute

  1. 0 to 5SettlePairs sit together. One Chromebook opens to the Code Editor. Worksheets out. I name the first driver: the student whose birthday is sooner.
  2. 5 to 10HookI play Lost in the Lab on the projector. The class calls out the denary for 0110 and 1101. I stop at the 8-bit door. "Today you'll read the code behind one door."
  3. 10 to 18PredictLids down. Each student writes P1 to P3 alone for 4 minutes. Then pairs agree on one answer for each, on the mini whiteboard. Boards up on my signal. I note the spread and say nothing yet.
  4. 18 to 23RunLids up. Copy the starter from the worksheet page and run it three times. Tick right predictions. I ask who wrote quote marks in P1 or missed them in P3. Two pairs explain.
  5. 23 to 35InvestigateSwap driver. I1, the trace table, first, on paper. Then I2 and I3 on the laptop. For I2, they predict before they change the line. I show how to press Stop.
  6. 35 to 50ModifyM1, then M2. Swap driver at minute 43 when the timer rings. I walk the room with my class list.
  7. 50 to 56MakePairs who finished M2 start the Make task. Others finish M2. Anyone done plays the full game and looks for its bugs.
  8. 56 to 60ExitOne line on the back of the sheet: "Why does line 17 need str()?" Sheets in the tray. Close the Code Editor tab.

Check: 5 + 5 + 8 + 5 + 12 + 15 + 6 + 4 = 60 minutes.

Support ideas

Slow typists

  • Nobody types the starter. They copy it from the worksheet page. In my first try, typing it by hand took three pairs 12 minutes.
  • M1 is a one-line change. M2 changes about four lines. A slow typist can do both.
  • The navigator reads each line aloud before the driver types it. Fewer typos, and both students think about the code.

Typos and errors

Each pair gets this card. It comes from my own bug diary.

Got an error? Read the LAST line first.

  • SyntaxError: expected ':' Add a colon to the end of the if, while, for or def line.
  • IndentationError The line after a colon moves in 4 spaces.
  • NameError ... Did you mean Check your spelling. Python is guessing for you.
  • TypeError ... str ... int Text and a number got mixed. Use commas in print, or str().
  • No error, but it never stops? Press Stop. Print the type of each value.

A pair with a hand up must tell me the error's name and line number. Most fix it while they tell me.

Checking that every student codes

  • Each student writes P1 to P3 alone first, on their own sheet. Nobody can copy a partner's guess.
  • Drivers swap when the timer on the screen rings, at minutes 23 and 43. I announce it every time.
  • I walk with my class list. At minutes 30 and 45, I tick who is driving. I ask the navigator, not the driver, to explain the line just typed. Anyone with no tick by minute 45 drives for the rest of the lesson.
  • The exit line is written alone. It tells me who understood I2.

Other students

  • Stuck on M2: I give a hint strip. It says: "Add and len(wrong) < 2 to line 17. Then use if and else after the loop."
  • Finished early: the Make task. Then find a bug in the full game. There is one about the dark server room.
  • Not confident with English: I read each question aloud at the start of each stage. The story words are short on purpose.
  • Laptop or Code Editor won't load: the pair runs the starter on the worksheet page. It runs there with nothing to install.

Why PRIMM, and what I'm unsure about

PRIMM stands for Predict, Run, Investigate, Modify, Make. The PRIMM Quick Read explains it. I chose it because my old lessons started with a blank screen. Half the class froze.

What I'm unsure about: 8 minutes of Predict with lids down felt long for some students. Two of them wanted to "just try it". I don't know yet if the wait helps them or loses them. I'll ask my mentor to watch the next lesson.
