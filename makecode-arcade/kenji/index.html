A trap I fell into

My first version used "on overlap tile" for the canal and the flag. It ran fine in JavaScript. Then I clicked Blocks and back. The code broke.

Blocks puts event blocks before "on start". My tile pictures are set in "on start". So the events asked for a tile that did not exist yet. The editor said "used before its declaration".

The fix: the flag became a sprite, with its own kind. The canal check moved into the game loop, which only runs after "on start". Now the code survives the trip to Blocks and back. I checked.

The crow rule, side by side

This is the event my students argue about most. Blocks to text is a big step, so I show both.

JavaScript
sprites.onOverlap(SpriteKind.Player, SpriteKind.Enemy,
  function (sprite, otherSprite) {
    if (sprite.vy > 0 && sprite.bottom < otherSprite.y) {
        otherSprite.destroy(effects.disintegrate, 200)
        sprite.vy = -100
        info.changeScoreBy(3)
    } else {
        info.changeLifeBy(-1)
        scene.cameraShake(4, 300)
        tiles.placeOnRandomTile(sprite, DOOR)
    }
})
Python

The Python names come from the editor itself. I left out the sound line to fit.

Read it out loud. "Falling, and your feet are above its middle? You win. Any other touch? You lose a life." Players learn that rule in one try. It feels fair because it is exact.

Tuning the jump

A jump in Arcade is two numbers. ay pulls the bot down, in pixels per second, per second. Pressing A sets vy to -150, an upward speed. Kopi Run uses ay = 350.

  • Height: 150 × 150 ÷ (2 × 350) = 32 pixels. That is 2 tiles.
  • Time in the air: 2 × 150 ÷ 350 = 0.86 seconds.
  • Distance: the bot runs at 80 pixels a second. 80 × 0.86 = 69 pixels, about 4 tiles.

So my level rules are simple. Steps are 1 tile high. Gaps are 3 tiles wide at most. A 4-tile gap is possible on paper. In the playtest nobody made it.

Playtest notes from 2 rounds

The students and their words are made up, like me. The numbers are the game's real settings in each version.

Round 1: version 1, four Sec 2 students

Version 1 had ay = 500. A crow hit took a life with no sound. Falling in a canal restarted the whole level.

  • Note 1. Three of four fell in the first canal. They blamed the keyboard. The jump was 22 pixels high and 0.6 seconds long.
  • Note 2. Student A lost two lives to crows and did not notice.
  • Note 3. Student B fell in a canal near the flag. Back at the start, with every cup back too. She stopped playing.
  • Note 4. Student C landed on a crow and said, "Why didn't it die?"

Changes for version 2

  • From note 1: ay down to 350. The jump is now 2 tiles high.
  • From note 2: a crash sound and a screen shake. You also go back to the door.
  • From note 3: a fall sends you to the door. Cups you took stay taken.
  • From note 4: the stomp rule. Land on a crow for 3 points.

Round 2: version 2, four other Sec 2 students

  • Note 1. Level 2 had a 4-tile gap. Nobody crossed it in 5 tries. The maths said 69 pixels of air for 64 pixels of gap. Too tight.
  • Note 2. Student D stomped every crow on purpose. He said it was the best part.
  • Note 3. Student E asked where to go after the high platform.
  • Note 4. Student F lost a life at the end of level 2. The long walk back from the door made him groan.

Changes for version 3, the game above

  • From note 1: the gap is now 3 tiles.
  • From note 2: nothing. Stomping is the fun, so it stays.
  • From note 3: a row of cups on the high platform points the way.
  • From note 4: nothing yet. See what I would change.

Starter project

For the class I cut the finished game back into a starter. The levels, the bot and the crows are done. Students fill 3 gaps:

  1. The bot can jump in mid-air, again and again. Fix it with an if.
  2. Cups do nothing. Write the overlap event and the score.
  3. The flag goes nowhere. Use the level variable to load level 2, then win.

What I would change

Falling near the end of level 2 sends you back to the door. That is a long walk, and it feels like punishment. A checkpoint tile halfway would fix it. It is also a good stretch task for fast teams.

The pasted levels show as grey code blocks in Blocks. Students can't draw on them in the tilemap editor. Teams that want new levels draw a new tilemap and swap it in. That takes a demo.

And there is one jump height. I would like a higher jump when you hold the button longer. That needs a timer, and more code than a Sec 2 starter should hold.
