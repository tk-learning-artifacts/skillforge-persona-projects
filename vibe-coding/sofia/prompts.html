11 prompts, two evenings, one camp in between. My three best are marked. Each card says what I asked, what Claude gave, what I changed and how I checked.

Run these prompts yourself and you'll get different code. That's normal. Each prompt lists what the game must do, so you can test Claude's answer against the list. Prompts 6, 8 and 9 came from my campers' bug-hunt notes.

Evening 1: the first game

1. The brief Best

Make a one-file HTML game for kids aged 8 to 12 at a holiday camp. Theme: a kopitiam drink stall in Singapore. A customer orders a drink in kopitiam code, like "Teh C peng". The player builds it with buttons: - Kopi or Teh - milk: condensed, evaporated or none - sugar: none, less, normal or more - hot or iced Then they press Serve. A right drink scores a point. A wrong drink says what was wrong in one short sentence. No libraries, no images from the internet, no sound. Buttons at least 48 pixels tall, for small fingers on an iPad. Show the code first, then a list of what I should test.

What Claude gave
A working game in the artifact window, first time. Big buttons, a ticket, a score. Its test list had 8 items, like "try every sugar level".
What I changed
The milk words. Claude's table said C means condensed milk and plain Kopi means evaporated milk. That's backwards. I fixed it by hand. I also removed "Kopi kosong" and "Teh kosong". My sources don't agree on what they mean.
How I checked
I read every code word against the Wikipedia kopi table and a teh ordering guide. Then I played 20 orders.

Why it's my best: it names the age, the device, every button, and what I don't want. "No sound" saved me from a cash-register noise in a room of 18 kids.

2. Put the words in one place

Put all the order code words in one table at the top of the script, with a comment on each row. I want to fix a code word without reading the rest of the program.

What Claude gave
The PARTS table: each choice with its key, its code word and a label. The rest of the game reads from it.
What I changed
Nothing. I wish I'd asked for this in prompt 1. Fixing the milk would have taken one minute instead of ten.
How I checked
I changed "gah dai" to "GAH DAI" as a test. The ticket and the code board both changed.

3. Levels for mixed ages Best

Add three levels for mixed ages. Level 1 orders use only the drink and milk words (Kopi, Kopi O, Teh C). Level 2 adds sugar words. Level 3 adds peng. Move up a level after 5 right in a row. Show the level on screen.

What Claude gave
A level counter, and a filter that picks orders for the level. Level 1 has 6 orders, level 2 has 22, level 3 has all 44.
What I changed
One line: the same order can't come twice in a row. With only 6 level-1 orders, it often did.
How I checked
Played to level 3 twice and counted the streak each time.

Why it's in my best three: it says exactly which words belong to each level, and the rule for moving up.

4. The code board

Add a code board under the game that shows each code word and what it means. Include the "no word" choices too, like no peng means hot. Add a button to hide and show it.

What Claude gave
A two-column list with a Hide button.
What I changed
Nothing.
How I checked
Read it against my sources, row by row.

5. Draw the drink

Draw the drink as a simple flat SVG that changes as the player taps. Hot drinks in a cup with a saucer. Iced drinks in a tall glass with ice cubes. Show sugar as cubes beside the cup. Also write the drink in words under it, so colour is never the only clue.

What Claude gave
A cup and a glass, and up to 3 sugar cubes. The brown gets lighter with milk.
What I changed
Nothing yet. Prompt 8 came after camp.
How I checked
Built all four sugar levels, hot and iced.

Day 3 of camp: the bug hunt

Pairs had the game for two minutes and tried to break it. Each pair wrote one bug on a sticky note. The notes are on the project page. My campers are made up, like me.

Evening 2: fixing and growing

6. The campers' bugs Best

My campers found these bugs. Fix each one, and tell me which lines changed. 1. Tapping Serve twice fast scores two points for one drink. 2. After a wrong drink, the next order appears after 1 second. Kids can't read why they were wrong. Keep the wrong cup on screen so they can fix just the wrong part. 3. On a small phone, the Serve button is below the bottom of the screen.

What Claude gave
A lock on Serve while the customer talks. A wrong cup now stays. On narrow screens, the order and the buttons stack, with Serve right under the choices. It listed the changed lines for each fix, as asked.
What I changed
The customer's words. Claude wrote "Incorrect milk selection." I rewrote each message to give the rule, like "C means evaporated milk. You gave me condensed milk."
How I checked
I asked the camper who found each bug to try again. Bug 1's finder tapped Serve as fast as she could. One point.

Why it's in my best three: numbered bugs, each with what happened and what should happen. Asking "which lines changed" let me check each fix.

7. Tests

Write a test function that builds every valid order name, turns it back into a drink, and checks it matches. Also check that "Kopi kosong" is refused. Show the results on the page as "x of y passed". Do not use a test library.

What Claude gave
A parse() function that reads an order, and the tests. They run when the page loads.
What I changed
Nothing. I added a few test names in plain English, so a camper can read them.
How I checked
I broke the table on purpose, putting C back on condensed milk. Tests failed. I put it back, and all 50 passed.

8. Kopi and teh look the same

Campers say kopi and teh look the same colour in the cup. Make the six drink colours easier to tell apart, in light and dark mode. Keep the words under the cup.

What Claude gave
A colour table: darker browns for kopi, redder browns for teh.
What I changed
A comment, to say the words matter more than the colours.
How I checked
Showed two cups side by side to three campers. All three got them right.

9. Rush mode

Add a Rush mode for early finishers: 90 seconds, all 44 orders, code board hidden. A Peek button shows the board for 5 seconds. A wrong drink moves on to the next order. At the end, list each mistake with the right answer.

What Claude gave
A timer bar, the Peek button, and an end screen of mix-ups.
What I changed
Peek went from 5 seconds to 3. With 5, campers just waited it out.
How I checked
Played three rushes. Made mistakes on purpose and checked the end list.

10. Call it mode

Add a third mode called Call it. Show a finished drink and three order codes. One is right. The other two are each one part away from it. If the player picks a wrong one, tell them what that code would mean.

What Claude gave
The mode, with "near miss" answers. A wrong answer greys out, so you can try again.
What I changed
The wrong-answer message, to be shorter.
How I checked
Watched two of the youngest campers play it for five minutes. Neither asked me a single question.

11. The demo

Add a demo mode that plays the game by itself for exactly 90 seconds, for a parents' showcase screen. Use the real buttons, and show a ring where it taps. Put a caption under each part. Use these captions and times: [I pasted my script here]. Add play, pause, a seek bar and chapter buttons.

What Claude gave
A timeline of steps, each with a second and an action. Seeking restarts the game and replays every step up to that second.
What I changed
Nothing in the code. I rewrote my captions twice, because the first ones were too long to read in time.
How I checked
Watched it to the end, then jumped to each chapter.

What I learned about prompting

  • Ask for the structure you'll need to fix things, early. Prompt 2 should have been part of prompt 1.
  • Claude was confident and wrong about the one fact I cared most about. Check facts outside the code too.
  • Kids' bug reports make great prompts once you add "what should happen instead".
  • "Tell me which lines changed" turns a fix I'd have to trust into one I can check.
