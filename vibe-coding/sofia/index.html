I'm Sofia. I run holiday camps for mixed ages. My June camp had 18 campers aged 8 to 12. Most had heard an adult order "Kopi O" at a hawker centre. Very few knew what it meant. So the code is a puzzle they already half-know. That's my favourite kind.

This is my end project for the Vibe Coding module. Claude wrote most of the code. My campers broke it, and I fixed it. Everything is here: the game, a 90-second demo, my prompt log, and what I changed and why.

How to play

  1. Read the order on the ticket.
  2. Tap one button in each row: drink, milk, sugar, and hot or iced.
  3. Check the cup. The words under it say what you made.
  4. Tap Serve. If something is wrong, the customer says which part and why.

Three modes, for three kinds of camper

  • Learn is for everyone at the start. No timer, and the code board stays open. Five right in a row moves you up a level. Level 1 is only drink and milk words. Level 2 adds sugar. Level 3 adds peng.
  • Rush is for the camper who finished early. 90 seconds, the board is hidden, and Peek shows it for 3 seconds. At the end you see every mix-up with the right answer.
  • Call it flips the game. You see the drink and pick its order from three. Younger campers liked this best, because there's no building and no clock.

There is no sound and no class leaderboard. My quiet campers play without anyone hearing them get it wrong.

    The script

      How I built it

      • I used Claude in a browser. When Claude writes a small web app, it can show it in an artifact window beside the chat. I could play each version the moment it was written.
      • 11 prompts in all, over about two hours on two evenings. The prompt log has every one, word for word.

      Checking the kopitiam facts

      Claude's first code table was wrong in a way I'd have missed if I didn't drink kopi. It said C means condensed milk, and plain Kopi uses evaporated milk. It's the other way round. Plain Kopi has condensed milk, C means evaporated milk, and O means no milk. It also asked for "Kopi kosong". My sources only list kosong with O or C, like "Kopi O kosong". So I took plain kosong orders out. I fixed the table by hand, and I checked every word on the code board against the sources below.

      Under the hood

      The code is in three plain JavaScript files, with no libraries.

      • kopi.js holds the order rules: the word table, the 44 drinks, and the customer's messages. No page code, so it can be tested on its own.
      • game.js draws the stall and runs the three modes.
      • demo.js runs the 90-second demo, using the real buttons.

      The word table sits at the top of kopi.js. To fix a word, you change one line. This was my prompt 2: I wanted to fix facts without reading the whole program. Here is the milk part:

        Reflection: what I changed and why

        • I swapped condensed and evaporated milk in the word table. Claude had them the wrong way round.
        • I took out plain "Kopi kosong" and "Teh kosong" orders, because I couldn't find them in my sources.
        • I rewrote every customer message. Claude's said "Incorrect milk selection." An 8-year-old needs the rule, like "C means evaporated milk."
        • I cut the Peek time from 5 seconds to 3. Campers just waited with the board open.
        • I stopped the same order coming twice in a row. Two campers thought the game was stuck.
        • Every bug-hunt note above became a prompt, and I tested each fix with the camper who found it.

        How much was AI and how much was me

        I marked every line I typed with "// Sofia". There are 23 of them in 647 lines of code. That's under 4%. Claude wrote the rest, including the tests and the demo player.

        That number makes me look lazy, and it misses most of the work. The ideas were mine and my campers'. The three modes came from watching who got bored and who froze. The facts were mine to check, and Claude got the most important one wrong. I'd say Claude did 90% of the typing and 30% of the thinking.

        Rubric check

        • App works in the browser. Yes. All three modes, on a phone-width screen and a laptop, in light and dark mode. The tests pass on load.
        • Readable code that follows good practice. Mostly. The rules are apart from the screen code, the word table is in one place, and the tests run without a library. But game.js has one long mount() function. If a camper asked me where Rush lives, I'd have to scroll.
        • Precise, reproducible prompts. My first prompt names the age group, every button, the device and what I don't want. Claude will write different code each time. But anyone can check the result against the same list.
        • Fair reflection on AI vs human effort. I've given the line count and said why I think it undersells the human part. You might disagree. Typing is effort too.

        What I would change

        Kopi Rush needs reading. A 7-year-old who reads slowly can't play Learn mode alone, and Rush punishes slow readers most. Next camp I'd add a "read it to me" button. I'd also add Milo and a few more drinks, because the campers kept asking for them. Finally, the game teaches the code, not what's in the cup. A kopi with normal sugar has a lot of sugar. That's a good talk for another day.
