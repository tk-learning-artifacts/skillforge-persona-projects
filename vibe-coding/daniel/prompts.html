My prompt log

Every prompt I sent ChatGPT for Fair Picker, word for word. I didn't tidy them afterwards. My best three are marked.

  • Tool: ChatGPT in Chrome. Each answer went into CodePen to run.
  • When: two evenings in one week. Prompts 1 to 4 on the first, 5 to 9 on the second.
  • Each entry has five parts: the prompt, what ChatGPT gave, what I changed, why, and how I checked.
  • P-numbers match the tags in the code. The code page shows which lines came from which prompt.

If you run these prompts yourself, you'll get different code. ChatGPT never answers the same way twice. What you can repeat are the checks. Each strong prompt says what the code must do, so you can test any answer against it.

P1. The first try

Prompt

make a random name picker for my class

What ChatGPT gave
A box for names and a button. Each press picked a name with Math.random(). It ran first time.
What I changed
Nothing. I threw it away.
Why
With 5 names, it picked the same name twice in 10 presses. Of course it did: I never said "no repeats". I also never said the class size, the device, or that it had to save.
How I checked
Pressed the button 10 times with 5 names and wrote down each pick.

P2. The real brief Best prompt

Prompt

I teach a Sec 2 class of 28 students. Build a web app as one HTML file with a <style> section and a <script> section. Use plain JavaScript, no libraries. It must: 1. Let me paste a class list, one name per line, and save it. 2. Pick a random student with a big Pick next button. Nobody is picked twice until everyone has had a turn. Then start a new round. 3. Show how many students are left this round. 4. Have an Undo button for the last pick. 5. Make random groups of a size I choose, from 2 to 6. Write comments a beginner can follow. Text must be big enough to read on a classroom projector. After the code, list 5 tests I should do by hand.

What ChatGPT gave
One file of about 150 lines that worked in CodePen. It kept a "remaining" list for the round. The groups used sort(() => Math.random() - 0.5) to shuffle. Every name went onto the page with innerHTML. Its 5 tests were sensible, like "pick until the list is empty".
What I changed
Nothing yet.
Why
All 5 of its tests passed, so I thought it was done. This is where I was still vibe coding: I ran it, but I didn't read it. Prompts 3 to 8 are me finding out what I'd missed.
How I checked
Ran its 5 tests. Picked through 5 names twice: no repeats inside a round.

P3. Saving

Prompt

Save the class list and the picks in this round in localStorage, so a page refresh in the middle of a lesson loses nothing. First explain localStorage in two sentences for a beginner.

What ChatGPT gave
A clear explanation: it keeps text in this browser, even after you close it. It only stores strings, so objects go through JSON.stringify. But the code saved only the names, and only when I pressed Save list.
What I changed
I added who is left and who was picked to what gets saved. Every change now saves at once. I wrapped loading in try and catch, in case storage is blocked.
Why
I took "this saves your data" at face value. Then I refreshed after 3 picks and the round started over.
How I checked
Picked 3, refreshed, and the counter still said 3 picked. MDN's localStorage page confirmed the data has no expiry time.

P4. Nobody left alone Best prompt

Prompt

Here is my makeGroups function. With 28 students and groups of 3, I get nine groups of 3 and one student alone. Change it so no group is smaller than the size I chose. Extra students join existing groups, one each. Keep it under 15 lines and don't change how it is called. [I pasted the makeGroups function here]

What ChatGPT gave
A shorter function. It worked out the number of groups with Math.round(list.length / size), then dealt students into the groups like cards.
What I changed
Math.round became Math.floor. That was the whole fix.
Why
28 in groups of 3 worked now. But 5 students in pairs gave 2, 2 and 1. Math.round(2.5) is 3, so it made three groups. Rounding down makes two groups, of 3 and 2.
How I checked
I asked ChatGPT for a test loop. It tries every class size from 2 to 30, with group sizes 2 to 6. It prints any group smaller than the size I chose. After my change, it printed nothing. The only exception is a class smaller than the group size, which makes one group.

P5. Is the shuffle fair?

Prompt

Is list.sort(() => Math.random() - 0.5) a fair shuffle? Answer yes or no first, then explain why.

What ChatGPT gave
"Not perfectly." Then it said the method is fine for casual uses.
What I changed
Nothing in this step. I nearly stopped here, because a classroom felt casual.
Why
Then I read javascript.info's shuffle task. It says not all orders are equally likely with this trick. I wanted to see it, so I built the test on the code page. In a class of 28, No. 1 came first about 9 times in 100 shuffles. Fair is about 3.6. That's not casual if you're No. 1.
How I checked
20,000 shuffles, counting who lands first.

P6. Fisher-Yates

Prompt

Rewrite shuffle using the Fisher-Yates shuffle. Put a short comment on the line that picks the random spot.

What ChatGPT gave
A loop that walks back from the end of the list. It swaps each name with a random one at or before it.
What I changed
I made it copy the list first, with list.slice().
Why
It shuffled the class list itself. After making groups, the Class tab showed my class in a jumbled order.
How I checked
The same 20,000-shuffle test. Every student now lands first about 3.6 times in 100. I also made groups and checked the Class tab kept its order.

P7. Security check Best prompt

Prompt

Check this code for security problems. The names come from a textarea that anyone at the teacher's desk can type into. For each problem, give the line, what could go wrong, and the fix. Then rewrite render() so no user text goes through innerHTML. [I pasted the render function here]

What ChatGPT gave
It found the problem: names went onto the page with innerHTML, so a "name" could be HTML that runs code. It rewrote render() with a small helper that builds each element and sets its text.
What I changed
I kept the helper. I added a part for aria- attributes, which it had dropped from the tabs.
Why
I tried MDN's example string as a name before the fix: <img src=x onerror=alert(1)>. An alert box popped up. A student at my desk could do worse than an alert.
How I checked
The same string after the fix shows as plain text. It's at 1:10 in the demo.

P8. Absent students

Prompt

Add a list of students with a tap to mark them absent. Absent students are skipped by Pick next and left out of groups. When they come back, they still get their turn this round.

What ChatGPT gave
Tap-to-mark buttons that worked. But marking someone absent took them out of the round's list. Unmarking didn't put them back.
What I changed
The round's list keeps everyone. Pick next skips absent students at the moment it picks.
Why
My prompt said "they still get their turn". The code didn't do it. This one surprised me, because the prompt was clear.
How I checked
Marked No. 3 absent. Picked everyone else. Unmarked No. 3 and pressed Pick next: No. 3 came up.

P9. Tabs

Prompt

Split the page into three tabs: Pick, Groups and Class. Use role="tab" and aria-selected so a screen reader knows which tab is open.

What ChatGPT gave
Three tab buttons, with each panel hidden until its tab is pressed.
What I changed
Nothing. I added one line myself: the Class tab opens first when there's no class yet.
Why
A new user saw "No class yet" and didn't know where to go.
How I checked
Used the whole app with Tab and Enter only, no mouse.

Changes with no prompt

These I typed myself. They're tagged "Me" in the code.

  • The Use register numbers button. Names on a shared lab laptop stay there until someone clears them.
  • The Forget this class button, for the same reason.
  • Two students with the same name get "(2)", so they stay two people.

What I learned about prompting

  • Numbers make prompts testable. "28 students, groups of 3, nobody alone" told me what to check.
  • Asking for the tests in the same prompt (P2) was useful. But its tests only checked what I'd asked for, not what I'd forgotten.
  • Pasting one function and describing one bug (P4, P7) got better fixes than "fix my code".
  • "Yes or no first" (P5) stopped a long answer. It didn't stop a wrong-ish one.
