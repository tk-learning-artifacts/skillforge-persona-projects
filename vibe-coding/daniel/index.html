Fair PickerA name picker with no repeats, and a group maker. Built with ChatGPT for my Sec 2 class.

I kept picking the same five hands. A random name picker fixed that, until it picked the same boy twice in a row. So I built one that gives everyone a turn before anyone gets a second.

I'm Daniel. I've been a trainer for six months. I teach a Sec 2 coding enrichment class of 28 on Wednesday afternoons. This is my end project for the Vibe Coding module. ChatGPT wrote most of the first code. I tested it, found six problems, and fixed them. Some fixes I asked for, and some I typed myself.

Use it

Start on the Class tab. Paste some names, or press Use register numbers. Then pick, mark someone absent, and make groups.

Fair Picker needs JavaScript to run.

Your list stays in this browser. Nothing is sent anywhere. Open it full screen for a projector.

What it does

  • Pick next chooses someone who hasn't had a turn this round. When everyone has had one, New round puts them all back.
  • Undo puts the last pick back.
  • Absent students are skipped, but keep their turn for when they're back.
  • Groups of 2 to 6. Spare students join groups one each, so nobody is left alone.
  • The class and the round survive a page refresh.

How I built it

  • ChatGPT in Chrome wrote the code. CodePen ran each version.
  • I used 9 prompts over two evenings. The prompt log has every one.
  • I checked lines against MDN, and built a test for the shuffle.
  • It took about 1 hour of prompting and 2 hours of testing and reading. The testing found every bug.

Is this vibe coding? Andrej Karpathy coined the term in a post in February 2025. Simon Willison wrote in March 2025 that vibe coding means not reviewing the code the AI writes. By that line, my first two prompts were vibe coding. After that I read every line. So the finished app is AI-assisted coding.

Why my students aren't building this one yet

I wanted my class to make their own pickers. Then I read the terms. ChatGPT needs users aged 13 or over, and under-18s need a parent's permission. CodePen's terms say under-18s can't have their own account. A guardian can sign up for a 13 to 17 year old. Most of my Sec 2s are 14. So for now, I build and they test. I need to sort out consent before they prompt.

Reflection: what I changed and why

ChatGPT's code worked the first time I ran it. That fooled me. Each of these problems only showed up when I tested something on purpose.

How much was AI and how much was me

I tagged every block of the code with who wrote it. The code page counts the lines:

  • AI ChatGPT wrote it and I kept it: 101 lines (39%).
  • AI, then me ChatGPT wrote it and I changed it: 121 lines (47%).
  • Me I wrote it: 35 lines (14%).

So ChatGPT wrote the first version of 86% of the lines. That clears the brief's 50%. But lines aren't the whole story. Most of my changes were one or two lines. Finding each one took longer than all the typing. The AI did most of the writing. I did most of the testing and checking. Without the testing, I'd have shipped all six bugs.

Rubric check

  • App works in the browser. Yes. I tested it in Chrome on a phone-width window and a wide screen. It also works with the keyboard alone. The class survives a refresh.
  • Readable code that follows good practice. Mostly. Small helper functions, comments a beginner can follow, and no typed text through innerHTML. The weak spot: mount() is about 185 lines long. I'd split it.
  • Precise, reproducible prompts. My best three (P2, P4, P7) give the class size, the rules and the tests. You'll get different code if you run them, because ChatGPT never answers the same way twice. But you can test the new code against the same checks. P1 is in the log as a bad example.
  • Fair reflection on AI vs human effort. I think so. The counts are above, and they come from tags in the code, not my memory. I've also said what the counts leave out.

What I would change

It holds one class, in one browser. If I switch laptops, my list is gone, and there's no export. A "copy my class" button would fix that.

The bigger question is about people, not code. The picker is fair to the maths. It isn't always kind to a quiet student who dreads being called. Should I add a Pass button that keeps their turn? I don't know yet. I'd like to try "phone a friend" first and see.

One thing still confuses me. I can see in the chart that the sort shuffle is unfair. I can't fully explain why. javascript.info says the result depends on how each browser's sort works inside. I'm taking that on trust for now.
