Lesson 2 of 2 · Scratch

Teach the key to Scratch

Pairs turn their group's key from lesson 1 into a Scratch bot. It asks the questions and names the object.

  • Sec 1 G2 or G3 Science
  • 60 minutes
  • About 36 students, 18 pairs
  • Computer lab, one computer per pair

Learning goals

  • CS Code a key with input ("ask and wait"), selection (if-else) and a loop ("forever").
  • Science Justify each question: which property it tests, and why it splits the objects.

Success criteria

  1. Our bot asks our group's questions in the right order.
  2. It names all 5 objects correctly when another pair tests it.
  3. We can point to the input, the decision and the loop in our script.
  4. We can explain one bug we found and how we fixed it.

Materials

  • The lab, with scratch.mit.edu checked the day before on a student log-in.
  • key-bot-starter.sb3 in the class folder. The trainer loads it on every computer during the break before.
  • Each group's key from lesson 1, returned with the swap-test notes.
  • A test log sheet per pair: object, bot's guess, right or wrong.
  • Backup: printed block strips for each pair, in case the lab is down.

The starter file

The first question is done. Pairs replace the two "say" blocks with the rest of their own key.

The finished model, for trainers, is Key Bot on the unit page. Do not show it before 40 minutes. Students' keys should look like their own, not like ours.

Trainer briefing

  • The common bug: a tester types "yes", but the script checks for "y". The bot then goes down the "no" path. Let pairs find it in testing, then show the fix below.
  • The second bug: an if-else nested in the wrong branch. Ask: "Read your key's step 1. Where does 'no' go? Where does your script send it?"
  • Drivers and navigators swap at the 25-minute checkpoint.

The "y or yes" fix

Scratch's "=" ignores capital letters, so "Y" equals "y". But "yes" is a different word. An "or" block accepts both.

Check questions

  1. In your script, which block is the input, and which block makes the decision? ("ask and wait" is the input. The if-else decides.)
  2. A tester typed "yes", and the bot went down the "no" path. Why? (The script compares the answer with "y". "yes" is not equal to "y", so the else branch runs.)

For every student

  • Pairs who struggle: code the model key from the unit page instead of their own. The blocks are printed for them in order.
  • Pairs who race ahead: add the cork. Add the "or" fix to every question. Then make the bot count how often it is right.
  • Few computers: three students per computer. The third is the tester, who keeps the log.
  • Lab down or Scratch blocked: pairs build the script with printed block strips. Another pair "runs" it by reading the blocks aloud. Save the strips in an envelope and code them next lesson.
  • Students do not need Scratch accounts. Nobody signs up in this unit.
