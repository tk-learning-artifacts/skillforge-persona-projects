01The whole program

# Two-sensor line follower, version 4 (final).
# Marcus Lee's robotics CCA, for the micro:bit V2 in MicroPython.
#
# Sensors: two TCRT5000 reflectance boards, analog out. Black tape reads HIGH.
# Motors: a DRV8833 dual H-bridge, powered by its own 4 x AA pack.
# Press A to calibrate and go. Press B at any time to stop.

from microbit import *

# ---- Numbers we tune. Change one per test run, and log it. ----
BASE = 900       # straight-line speed, 0 to 1023
TURN = 700       # how much the inside wheel slows on a turn
LOOP_MS = 30     # pause between readings
SPIN = 400       # wheel speed for the calibration sweep
MIN_GAP = 150    # tape and floor must differ by this much

# ---- Pins. Match these to your wiring diagram. ----
LEFT_EYE = pin1
RIGHT_EYE = pin2
LEFT_PWM, LEFT_DIR = pin8, pin13     # DRV8833 AIN1, AIN2
RIGHT_PWM, RIGHT_DIR = pin16, pin14  # DRV8833 BIN1, BIN2


def set_motor(pwm_pin, dir_pin, speed):
    # speed runs from -1023 (full reverse) to 1023 (full forward).
    # Only one pin of each pair gets PWM, so we never use more than 2 PWM pins.
    speed = max(-1023, min(1023, speed))
    if speed >= 0:
        dir_pin.write_digital(0)
        pwm_pin.write_analog(speed)
    else:
        pwm_pin.write_digital(0)
        dir_pin.write_analog(-speed)


def drive(left, right):
    set_motor(LEFT_PWM, LEFT_DIR, left)
    set_motor(RIGHT_PWM, RIGHT_DIR, right)


def calibrate():
    # Sweep both sensors across the tape: left, right, then back to the middle.
    # Returns the midpoint of the highest and lowest readings, or None.
    low, high = 1023, 0
    for left, right, ms in ((-SPIN, SPIN, 400), (SPIN, -SPIN, 800), (-SPIN, SPIN, 400)):
        drive(left, right)
        start = running_time()
        while running_time() - start < ms:
            for value in (LEFT_EYE.read_analog(), RIGHT_EYE.read_analog()):
                low = min(low, value)
                high = max(high, value)
            sleep(LOOP_MS)
    drive(0, 0)
    if high - low < MIN_GAP:
        return None
    return (low + high) // 2


def follow(threshold):
    # Sense, decide, act, until B is pressed.
    while not button_b.was_pressed():
        left_dark = LEFT_EYE.read_analog() > threshold
        right_dark = RIGHT_EYE.read_analog() > threshold
        if left_dark and not right_dark:
            drive(BASE - TURN, BASE)    # tape under the left sensor: steer left
        elif right_dark and not left_dark:
            drive(BASE, BASE - TURN)    # tape under the right sensor: steer right
        elif not left_dark and not right_dark:
            drive(BASE, BASE)           # tape between the sensors: straight on
        # Both dark: a sharp corner. Keep doing the last thing.
        sleep(LOOP_MS)
    drive(0, 0)


# ---- Main program ----
drive(0, 0)
while True:
    display.show("A")
    while not button_a.was_pressed():
        sleep(20)
    threshold = calibrate()
    if threshold is None:
        display.show(Image.NO)      # not over the tape: move it and press A again
        sleep(1000)
        continue
    display.show(Image.YES)
    sleep(600)
    follow(threshold)
    display.scroll(threshold)       # write this number in the run log

02How it is laid out

A judge, or a new team member, should find any part in ten seconds. So the file has four blocks, always in this order.

1. Numbers we tune

Every number we ever changed during testing sits at the top, in capitals, with a comment. Nobody digs through the loop to change the speed. In a run log, a student writes "BASE 900 to 950" and everyone knows what moved.

2. Pins

The pins get names: LEFT_EYE, RIGHT_PWM. If a wire moves, you change one line. The names match the labels on our wiring diagram.

3. Functions, one job each

  • set_motor turns one signed number into signals for one motor. Plus is forward, minus is reverse.
  • drive sets both wheels at once. The rest of the code only ever calls this.
  • calibrate sweeps the sensors over the tape and finds the threshold.
  • follow is the sense, decide, act loop.

4. Main program

Wait for A. Calibrate. Show a tick or a cross. Follow until B. Scroll the threshold so we can log it. Then go back to waiting, so we can run again without a reset.

03The parts students get wrong

Why only two PWM pins

The DRV8833 needs two inputs per motor, so four in all. But the micro:bit can run PWM on only 3 pins at once. A fourth one switches another off. So set_motor sends PWM to one pin of each pair and holds the other at 0. To reverse, it swaps them. We never use more than two PWM pins.

Why "above the threshold" means tape

Each sensor shines infrared light down and measures what bounces back. A light floor bounces a lot back, and the board gives a low number. Black tape soaks the light up, so it reads high. Most TCRT5000 boards work this way. A few work the other way round. Show the raw numbers on the screen before you trust this line.

Why the threshold is not a fixed number

The tape read about 840 in our CCA room and about 460 by the hall windows. No single number works in both. calibrate takes the highest and lowest readings it sees during the sweep, and uses the halfway point. If the two are less than 150 apart, it isn't over the tape. It shows a cross and waits.

Why nothing happens when both sensors see black

On a sharp corner, both sensors can sit on the tape for a moment. Both "steer" rules would fight. So the code keeps doing whatever it did last, which is usually the turn it was already making.

Why button B is checked every loop

B is the stop button. was_pressed remembers a press, so a quick tap is never missed. The battery switch is the second stop, and the one we teach first.

04What changed from version 1

Version 1 was 35 lines. It had a fixed THRESHOLD = 512 and no calibrate. BASE and TURN were both 700, so the inside wheel stopped dead on every turn. The tuning notes show each change and the test that drove it.
