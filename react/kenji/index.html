How a round works

  1. The teacher starts the 5-minute timer on the class laptop or the projector.
  2. A player taps +1 on the games they'd play again. They have 3 tokens. Two on one game is allowed.
  3. Take back fixes a mistake. Lock in adds their tokens to the hidden totals.
  4. A hand-off screen says "Pass the device to player 2". The next player starts with 3 fresh tokens.
  5. When time is up, voting closes. Reveal shows the leaderboard, with bars, ties sharing a place, and a little fanfare.

The genre buttons filter the list. Games load from games.json, so a class swaps in its own games without touching the code.

Why it plays like this

A vote board is a tiny game. So I designed it like one and playtested it with my class. The class and the notes below are made up, like me. The design changes are real: you can find each one in the code.

  • Note 1. In version 1, totals showed live. After three players, everyone piled onto the leader. So totals now stay hidden until the reveal.
  • Note 2. Votes were unlimited. One student pressed +1 forty times. Now there are 3 tokens, so each vote costs something, and players have to choose.
  • Note 3. Players couldn't tell when it was their turn. The hand-off screen fixed that, and it hides the last player's choices.
  • Note 4. The reveal was a plain list. Students asked for "the drum roll". So it has bars that grow and a gold shadow for first. A short sound plays, and you can switch it off.

Where the React ideas are

Here is the component tree. State is what a component remembers. An effect talks to the world outside React.

  • App: state for games, error, tries, myVotes, tally, players, handOff, genre, secondsLeft, running, revealed, sound. Effect 1 fetches games.json. Effect 2 runs the timer.
    • TokenBar: props total, left. A list of coins.
    • GenreFilter: props genres, current, onPick. A list of buttons.
    • GameList: props games, myVotes, canVote, onVote, onTakeBack.
      • GameCard, one per game, with key={game.id}: props game, mine, canVote, onVote, onTakeBack.
    • HandOff: props player, onReady.
    • Leaderboard: props games, tally, players, onNewRound. A sorted list with keys.
  • Props: each GameCard gets its game and two functions. It never changes the votes itself. It calls onVote, and App decides.
  • State: tokens left, the total spent and the filtered list are worked out on every draw. They are never stored.
  • Lists and keys: the leaderboard re-orders when votes change. Keys from games.json keep each row tied to its game. React's docs warn that index keys cause bugs when a list changes order.
  • Effects: the fetch effect shows Loading, an error with Try again, and uses an ignore flag. The timer effect clears its interval in the cleanup. Without that, Strict Mode would leave two timers running. The clock would tick twice a second.

Why I built React Pad

The module suggests StackBlitz for students. Its terms changed in September 2026. Section 2.5 now says users must be 18 or over. My students are 13 and 14. GitHub Codespaces needs a GitHub account. That means age 13 or over, plus the school's consent process. My class will write React for one double period.

So I made React Pad: a small editor page in this project. It needs no account and sends nothing anywhere. Here is what it does:

  • A tab for every file in the project. The preview updates as you type.
  • Development builds of React, so students see React's real warnings, like the missing key warning.
  • A console that also logs each fetch. With Strict Mode on, students see games.json fetched twice. That starts a good conversation.
  • Two switches: a slow network, to see Loading, and Break games.json, to see the error screen.
  • A pretend server that answers /games.json with a 404, like GitHub Pages would, and explains why.
  • Download, which gives a real Vite project as a .zip, with the student's changes.

It saves work in the browser on that device. Many schools give each student their own device. Some choose iPads, like Peicai Secondary, whose bundle includes a keyboard cover. Others choose Chromebooks.

How the app was deployed

The same files in React Pad are a Vite project. I ran npm run build, which writes the finished site to dist. I set base to './' in vite.config.js. Now every path is relative, and the app works in any folder. Then I published dist to GitHub Pages, in the app folder of this project.

How it meets the rubric

  • App works from start to endLoad, vote, lock in, hand off, reveal, new round. The timer closes voting at 0:00. I played full rounds at phone width and on a wide screen. I tried light and dark mode.
  • Uses props, state, lists and effectsSix components take props. There are twelve pieces of state and four lists with keys. Two effects both clean up.
  • Tasks fit students' levelSec 2 students who have done some JavaScript. TODO 1 is one attribute. TODO 2 copies a pattern that sits just below it. TODO 3 is for the few who finish early.
  • Plan works on school devicesReact Pad runs in the browser with no install and no account. The lesson has a device check and a plan B.

What I would change

The votes live in one browser. Refresh the page and they are gone. There is also nothing to stop a player from sneaking a second turn. For a class of 32, passing one device around takes about 10 minutes. A real fix needs a server and logins. That is a bigger project, with more privacy questions.

React Pad is not Vite. It has React and nothing else, so students can't add packages. It can't teach npm run build either. My class sees the deploy step on my screen, not on their own.
