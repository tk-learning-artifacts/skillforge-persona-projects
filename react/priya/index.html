Checkpoint: am I ready for React?

A small React quiz that tells each student which course outcomes to revisit. Students take it, then build it themselves from a starter in GitHub Codespaces.

I'm Priya. I plan courses for a team of four trainers. This term we run a 10-week web elective for four Sec 3 classes of about 30 students each. Before the React weeks, I want one short check that every class takes the same way. Then I want the students to see how that check is built. This project does both.

What it does

  • Three sets: HTML, CSS and JavaScript. Each has 5 questions on what students need before React.
  • Each question is tagged with an outcome from our course plan, like J2 "Make functions run at the right time".
  • After each answer, students see why, and a link to the MDN page that backs it.
  • The results screen marks each outcome Met or Revisit, then gives a one-line exit ticket, such as "JavaScript checkpoint: 4/5. Revisit: J2."
  • Students paste that line into the class form. I sort 120 lines by outcome, and every trainer knows which mini lesson to reteach.

The quiz stores nothing and sends nothing. The only data is the line a student chooses to paste.

Where the React ideas are

The module asks for components, props, state, a list and fetched data. Here is where each one lives. The source page shows the code.

  • Components: App, SetPicker, Progress, QuestionCard, ChoiceButton and Results.
  • Props: App passes each question, its outcome and an onPick function down to QuestionCard. QuestionCard passes one choice to each ChoiceButton.
  • State: the set, the loaded quiz, an error, a retry count, the question number and the answers. The score is worked out from the answers, so it is never stored twice.
  • Lists with keys: set buttons, progress dots, choices and outcomes. Every key is an id from the data, never the array index.
  • Effects: one effect fetches questions/<set>.json, shows Loading and an error, and uses an ignore flag in its cleanup. A second effect moves keyboard focus to each new question.

Where it sits in the course

A starter only works if it lands at the right week. This is the order my team teaches.

  1. Weeks 1 to 4: Web FoundationsHTML, CSS and JavaScript, ending with a plain JavaScript quiz page.
  2. Week 5: this lessonStudents take Checkpoint as an entry check, then finish its starter in Codespaces.
  3. Weeks 6 to 8: react.dev's tic-tac-toeThree 60-minute lessons: squares and clicks, lifting state up, then time travel.
  4. Weeks 9 and 10: their own appPairs build a small React app and deploy it with the same workflow.

Week 5 comes first on purpose. The starter uses ideas from Weeks 1 to 4, like map and fetch, in a React shape. The tic-tac-toe weeks then explain the parts students have already used.

Why Codespaces, and not StackBlitz

The module suggests StackBlitz. I checked its terms before planning a cohort around it. StackBlitz's Terms of Service were updated in September 2026. Section 2.5 now says users must be at least 18. It also says the service may not be used by anyone under 18. Our students are 15, so StackBlitz is out.

GitHub's terms allow accounts from age 13. GitHub Codespaces runs a full Vite project in the browser, so it works on Chromebooks. A personal account gets 120 core hours and 15 GB-month of storage free each month. A 2-core codespace uses 2 core hours per hour, so one 60-minute lesson costs about 2 of the 120.

I would have handed the starter out with GitHub Classroom. GitHub retired Classroom on 28 August 2026. So the starter is a template repository, owned by a school account, and each student makes their own copy.

The cost of this choice: every student needs a GitHub account, made with the school's consent process, before Week 5. Codespaces also needs several GitHub and Microsoft web addresses open on school Wi-Fi. The device check lists them.

How it meets the rubric

  • App works from start to endPick a set, answer 5 questions, see results, do it again or switch sets. A missing file shows an error with Try again, not a blank page. I tested every set at phone width, in light and dark mode, and with the keyboard only.
  • Uses props, state, lists and effectsAll four, listed above. The fetch effect also handles loading, errors and a late answer.
  • Tasks fit students' levelThe three TODOs follow the levels in the module's starter guide: fill the gap, finish the idea, make it new. Each one uses a Week 1 to 4 skill. The entry check shows who needs the hints first.
  • Plan works on school devicesEverything runs in Chrome on a Chromebook. Nothing is installed. The lesson has a device check a week before, and a plan B if Codespaces won't load.

What I would change

The lesson plan works on paper. A real Week 5 will be messier. Codespaces takes a minute or two to start, and 30 students starting at once on one school network is the risk I can't plan away. I gave it five minutes and a plan B. A trainer with a weaker network will need more.

The quiz is also only as good as its 15 questions. Three questions per outcome would be fairer than one or two. Then one slip would not mark a whole outcome "Revisit".
