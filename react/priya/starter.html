The task card

One page. Print it, or students open TASKS.md, which Codespaces opens for them.

Finish the Checkpoint quiz

Goal: a quiz that loads the set you pick, keeps score and tells you what to revisit.

Step 0. Predict, then run

Read src/App.jsx. Write down two guesses. What happens when you pick CSS? What score do you get for all right answers? Then type npm run dev in the terminal. Were you right?

Step 1. TODO 1 Load the set you picked

In src/App.jsx, change path so it uses setId. Test: pick CSS. The first question should ask about a .card selector.

Hint for step 1

Use a template string with backticks: `questions/${setId}.json`. No slash at the start, or it breaks on GitHub Pages.

Step 2. TODO 2 Keep score

In src/App.jsx, work out correct by comparing choiceId with question.answer. Test: one right and one wrong answer. The score should say 1 of 2.

Hint for step 2

=== gives true or false. That is exactly what correct needs.

Step 3. Save your work

Open Source Control on the left. Type a message, such as "Load sets and keep score". Click Commit, then Sync Changes.

Stretch. TODO 3 Outcomes to revisit

In src/components/Results.jsx, show each outcome as Met or Revisit. Use map with a key. Then add the outcomes to revisit to the exit line.

Hint for the stretch

For each outcome, find its questions with filter. It is met if every answer to them was right.

Set-up for the team, once per term

One trainer does this with the school's GitHub account. Then every class uses the same link.

  1. On GitHub, make a new repository called checkpoint-starter, with a README.
  2. Click Code, then Codespaces, then Create codespace on main.
  3. Drag checkpoint-starter.zip into the file list on the left.
  4. In the terminal, type unzip checkpoint-starter.zip, then cp -r checkpoint-starter/. ., then rm -r checkpoint-starter checkpoint-starter.zip.
  5. Commit and sync. Then stop the codespace at github.com/codespaces: the "..." menu, then Stop codespace.
  6. In the repository, open Settings and tick Template repository.
  7. Open a fresh codespace from the template once, as a student would. Check that npm run dev opens the preview.

Students then click Use this template, then Create a new repository. Each copy belongs to the student, so their commits are saved there. GitHub's guide to starting from a template also offers "Open in a codespace" straight away. I don't use it in class, because that work only lives in the codespace until the student publishes it.

What is in the starter

  • .devcontainer/devcontainer.json picks a Node.js 24 image, runs npm install once and opens TASKS.md and App.jsx. When Vite starts on port 5173, the preview opens beside the code.
  • vite.config.js lets Vite answer the ...app.github.dev address that Codespaces gives the preview.
  • public/questions/demo.json is a 3-question set, so the starter has something to show before TODO 1.
  • TASKS.md is this task card.

Testing it on a colleague

The module's guide says to test a starter on a colleague for 10 minutes and say nothing. Ravi, one of my trainers, did it. Like the students in the lesson plan, Ravi is made up for this example.

  • The starter ran with no edits. Ravi predicted the CSS button would do nothing. It loads the demo set, which surprised him. That is the point of step 0.
  • TODO 1 took him 2 minutes. He first wrote 'questions/setId.json', in plain quotes. I added the backticks to the hint.
  • TODO 2 took 1 minute. He asked where question came from. It is the line just above, so I left the code as it is.
  • The stretch took 9 minutes. That is fine for a stretch. I moved it after the Save step, so nobody skips saving to chase it.
