For teachers. Each walkthrough gives the flag, the steps and the idea the challenge is there to teach.

1. Read the rules

Flag: sf{permission_first}, in the last box of the rules page.

The idea: a CTF is legal because its owner invites you in. The first habit is to read what you may attack.

2. Where does this link go?

Flag: sf{login.merlionbank.com.sg}. The board also accepts the hostname on its own.

  1. merlionbank.com.sg.acct-unlock-sg.net. The owner is acct-unlock-sg.net. The bank's name is only a subdomain at the front.
  2. www.merlionbank-sg.com. A different domain. Anyone can register a name with a dash in it.
  3. merlionbank.com.sg@203.0.113.7. Everything before the @ is user information, not the host. The host is the IP address 203.0.113.7. The URL standard warns that this part can be made to look like a trusted name. That address is from a block reserved for examples, so it goes nowhere real.
  4. www.rnerlionbank.com.sg. "rn" looks like "m" in many fonts. It is a different domain.
  5. login.merlionbank.com.sg. The only one whose name ends in the bank's own domain. This is the flag.

The idea: read the hostname from the right. Then remember the whole message is still a scam. The fix for a scared student is the same either way: don't tap, check with the bank's own app or number.

3. Caesar's homework

Flag: sf{try_all_25_keys}. The shift is 7. The note reads MEET ME AFTER CCA. THE FLAG IS SF{TRY_ALL_25_KEYS}.

The idea: an alphabet shift has only 25 useful keys. Trying them all is quick, even by hand. Suetonius wrote that Caesar replaced each letter with the one three places on, so A became D. Modern ciphers have keys so long that trying them all is out of reach.

4. Encoded is not encrypted

Flag: sf{encoded_is_not_encrypted}. In CyberChef, "From Base64".

The idea: Base64 turns any data into plain letters and digits so it can travel as text. There is no key. The standard that defines it, RFC 4648, says base encoding does not give any real secrecy. It also notes that people have leaked passwords by thinking it did.

5. The club page

Flag: sf{the_browser_gets_everything}, in an HTML comment. There is also a paragraph hidden with CSS.

The idea: the browser downloads the whole page. Comments and hidden parts come too. The fix is to keep secrets on the server and never send them. A login with the check done on the server is the right tool.

A good follow-up question: my challenge board also runs in the browser. Can a student find the flags in its code? Partly. The flags are stored as hashes, so they are not in plain sight. A determined pair could still work some out. That is the same lesson, and I tell them so.

6. Build a passphrase

Flag: sf{long_beats_clever}, shown when every check passes.

An example that passes: kettle-orbit-mango-sock. Don't let students use it, or any shared example, for real.

The idea: NIST's current guidance asks for at least 15 characters when a password is used on its own. It checks new passwords against a list of common ones. It tells websites not to force symbol rules or regular changes. My "3 words" rule breaks that last point on purpose. I use it to make the passphrase easy to remember, and I ask students to spot the clash.

What students got wrong

My class is made up, like me. These are the mistakes I would expect, written as if I saw them.

  • Challenge 2: most pairs picked link 1. They saw "merlionbank.com.sg" at the start and stopped reading.
  • Challenge 4: three pairs tried Caesar shifts on the Base64 text for five minutes.
  • Challenge 5: six Chromebooks blocked view source. The printouts saved it.
  • Challenge 6: two pairs used their pair name with "123" on the end, then asked why it failed.
