Why forms, not fetch()

The module showed fetch() and a JSON API. I tried that first, and I got lost between the page code and the route code. So I went back to plain HTML forms, like the Flask Quickstart. The form posts to Flask. Flask saves, then redirects back to /. Flask builds the whole page from one template. It reloads the page each time, but every step is easy to point at. For my CCA students, that mattered more.

The redirect fixed a real bug. At first, /signup returned the page straight away. If you pressed refresh, the browser sent the form again. One fake student got signed up three times.

What I got wrong

1. No commit

My first INSERT looked fine. After a refresh, the list was empty. Python's sqlite3 opens a transaction for an INSERT, and I never called commit(). Every write route now commits.

2. A glued-together login

Version 1 built the login query with an f-string, and kept passwords as plain text. You can try it above. Version 2 uses ? and check_password_hash.

3. Too much data

My first table asked for a phone number and a parent's email. I asked myself what I would use them for. The answer was nothing. The teacher meets the students at the session anyway. Now it is first name, class and session.

4. Double sign-ups

Refreshing after signing up sent the form again. Now every form route ends with a redirect, so a refresh only reloads the page.

What I would change

My students never write a Flask route. Our managed school Chromebooks can't install Python, and I didn't want them on hosting accounts. So they design tables, write SQL and test my app. Building a route themselves would teach more. Next year I would book the computer lab for session 3.

The app also trusts whoever signs up. Anyone can sign up a made-up name, or someone else's name. And if two students take the last place at the same moment, both might get in. The code counts first and saves after. I am not sure yet how to fix that in SQLite. If you know, I would like to hear it.
