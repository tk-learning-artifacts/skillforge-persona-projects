Team Points

A two-screen SwiftUI app that keeps score in class quiz games. I built it in Swift Playgrounds on a school iPad.

I'm Daniel. I've been a trainer for six months. On Fridays my Sec 1 class plays a team quiz. I kept score on the whiteboard, and I kept losing count. Twice the class argued about who won. So for my Swift end project, I built the scoreboard I needed.

The brief asks for two screens, one interactive feature and basic styling. Here is where each part is:

  • Two screens: the team list, and one team's page. You move between them with navigation.
  • The interactive feature: giving and taking points. Screen 2 changes the score that screen 1 shows.
  • Styling: team colours, a rounded font, a crown for the leader and a rolling score.
  • Deliverables: the video walkthrough, the Playgrounds file and the README.

What I got wrong

I'm writing these down because my students will make the same mistakes. I made them both in one evening.

1. The score that reset itself

My first screen 2 kept its own score: @State private var points = 0. The buttons worked. The big number went up. Then I tapped Back, and the list still said 0 for every team.

It took me a while to see why. @State is a view's own copy. Screen 2 had a copy, and the list had another. Nothing joined them.

The fix is to keep the scores in one place: the list. Screen 2 borrows one team. Apple's docs say a @Binding can "read and write a value owned by a source of truth". Here the source of truth is the teams array on screen 1.

2. The error I didn't understand

So I changed screen 2 to @Binding var team: Team. Then the list would not build. Swift Playgrounds said:

cannot convert value of type 'Team' to expected argument type 'Binding<Team>'

I was passing a plain team, and screen 2 wanted a binding to one. The fix is two dollar signs. ForEach(teams) { team in became ForEach($teams) { $team in. Then TeamView(team: $team) works.

I checked this error text by building the broken version again. It is word for word what Swift prints.

3. Orange I couldn't read

I first set the app's accent colour to orange. The Reset button turned orange too, on a white bar. From the back of the room it was hard to read. Now .tint(.primary) makes the bar buttons black in light mode and white in dark mode.

What happened in class

The class and the students here are made up, like me. The app and its code are real.

  • I mirrored the iPad to the projector. The big score on screen 2 read well from the back row.
  • My first version had colour circles only. A student said Kopi and Teh looked the same from far away. So each team got a shape too: circle, triangle, square and star.
  • Teams cheered when the crown moved to them. I didn't plan that. It is the best part of the app.
  • I pressed Reset by accident once. That is why it now asks first.

Accessibility basics

I turned on VoiceOver and went through every screen. On iPad it is in Settings, then Accessibility, then VoiceOver. Then I checked each item against Apple's accessibility guidelines.

  • Each row reads as one line: "Milo, 15 points, in the lead". Before I added .accessibilityElement(children: .ignore), VoiceOver read the shape, name and number apart.
  • The point buttons say "Add 1 point", "Add 3 points" and "Take away 1 point". VoiceOver doesn't say "plus one".
  • The shapes are hidden from VoiceOver on screen 2. They add nothing when read aloud.
  • Colour is never the only clue. Apple's guide says to "convey information with more than color alone".
  • The point buttons are 80 by 64 points. Apple's default control size on iPad is 44 by 44.
  • White text on the team colours is 5.5 to 1 or more. Apple asks for 4.5 to 1 for text up to 17 points. The grey −1 button is 3.3 to 1, but its text is 28 points bold. Apple asks for 3 to 1 there.
  • Names and list scores use system text styles. They grow when you make text bigger in Settings.
  • With Reduce Motion on, the score changes with no roll and no pop.
  • In dark mode the team shapes are hard to see. I measured about 2 to 3 to 1 against the dark rows. The names still say which team is which.
  • The big score on screen 2 is a fixed 120 points. It does not grow with text size.

How it meets the rubric

  • Functionality. Both screens work, scores carry between them, and Reset asks first. I used it for two quiz lessons with no crash.
  • Code clarity. Four short files, one job each. The comments say where the state lives and why.
  • UI polish. Team colours, a rounded font, the crown, and the rolling score. It also works in dark mode.
  • Accessibility basics. VoiceOver labels, shapes, big buttons and Reduce Motion are done. Dark mode contrast for the shapes is not.

What I would change

The scores only live in memory. If someone closes the app, the scores are gone. A long sleep can do it too. That happened to me once, mid-lesson. Saving them means storing the teams on the iPad. I haven't learnt that yet. I would also give each team a lighter colour for dark mode.

A question I still have: is a scoreboard enough of an app for Sec 1? It taught me @State and @Binding. But it has no game in it. I'd like to hear from someone who has tried both.

As a starter for my class

To turn it into a starter, I would remove three things. Students then add them back:

  1. Easy: the +3 button. Copy the +1 button and change two numbers.
  2. Medium: the crown. Write isLeading so only the top team gets it.
  3. Hard: the binding. Screen 2 starts with @State, so the score is lost. Students fix it.
