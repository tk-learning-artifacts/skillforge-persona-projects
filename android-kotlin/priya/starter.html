Starter project and task card

Sec 3 pairs finish Word Wall from a starter that already runs. One task card, three levels, the same for all four classes.

Task card

Goal. Finish Word Wall: a list of course words you can search, open and save.

Open: the wordwall-starter project in Android Studio. Look for the 3 // TODO comments. View, Tool Windows, TODO lists them.

Step 0: Predict, then run (5 min)

Read WordListScreen.kt. Write 2 things the app will do, and 1 thing that won't work yet. Then press Run. Check your guess.

EveryoneTODO 1: two more words (8 min)

In AppWords.kt, add 2 words from week 6. Copy the AppWord above. Use ids 17 and 18.

Test: the list has a Week 6 header with 3 words under it.

Most pairsTODO 2: make search work (10 min)

In WordListScreen.kt, the search box changes nothing. Keep only the words that contain the search text.

Test: type "st". You see List and State, plus any new word with "st" in it. Rotate: "st" is still there.

StretchTODO 3: save for revision (15 min)

The switch does nothing. In MainActivity.kt, add a saved state next to search. Pass it to both screens. Update it when the switch changes.

Test: save 2 words. The list says "2 saved for revision" and those rows say Saved.

Hints, one at a time

Hint for TODO 1

Each word ends with a closing bracket and a comma: ),. The last word in a list needs no comma.

Hint for TODO 2

val shown = words.filter { it.word.contains(search.trim(), ignoreCase = true) }

Hint 1 for TODO 3

Copy how search is made. Use rememberSaveable(stateSaver = IdSetSaver) { mutableStateOf(emptySet<Int>()) }.

Hint 2 for TODO 3

Swap emptySet() for saved, and false for word.id in saved. Update with saved = if (on) saved + word.id else saved - word.id.

Red underline?

Click the red word and press Alt+Enter, or Option+Return on a Mac. Choose the import.

I wrote the TODOs as comments, not with Kotlin's TODO() function. TODO() throws an error when it runs, so the app would crash.

The same task in App Inventor

School C students without a laptop build Word Wall in blocks. The learning is the same: a list, a second screen, and data passed between them.

  1. Screen1: a ListView. Set ElementsFromString to the 18 words. Set ShowFilterBar to true. That is the search box.
  2. Screen2: two Labels, for the word and its meaning.
  3. In Screen1, use when ListView1.AfterPicking. Inside it, open another screen with start value, giving it ListView1.Selection.
  4. In Screen2, show get start value in the first Label.
  5. Stretch: store meanings in a second list, and look one up with index in list.

The Companion app shows it live on a phone or tablet. Many Chromebooks can also run the app on the same device.

How we check learning

  • During: the test line under each TODO. A trainer ticks it on a class list.
  • Exit ticket, three questions:
    1. Where does search live, and why not in the list screen?
    2. What would go wrong if it used remember instead of rememberSaveable?
    3. Which TODO was hardest? What helped?
  • Week 6 hand-in: see the device plan. It differs by route.

Notes for the four trainers

  • Use the same card in every class. If you change it, change it for the team.
  • Sync the starter on every device the day before. The first Gradle sync downloads the libraries.
  • Say "state goes down, events go up" in the same words. Students move between our classes for CCA and talk.
  • After your class, add one line to the team sheet: how long minutes 0 to 5 really took.
