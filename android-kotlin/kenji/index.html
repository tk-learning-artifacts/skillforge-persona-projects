Hitbox

A flashcard app for game-design words, built in Kotlin with Jetpack Compose. You say the meaning, check it, and earn a star.

I'm Kenji. I make games for a living and teach game design part-time. On Fridays I help run a school Infocomm Club: 20 Sec 2 and Sec 3 members, two hours a week.

Next term the club makes games. When they playtest, they need shared words. "It feels bad" is not feedback. "The hitbox is bigger than the sprite" is. So my app is a word bank of 12 game words, and it works like a game: a goal, a check, and a reward.

How it works: state, a list and two screens



  

    
State: two kinds

    
known is the set of words you know. Both screens need it, so it lives in their parent, HitboxApp. That is state hoisting.


var known by rememberSaveable(stateSaver = KnownSaver) {
    mutableStateOf(emptySet<Int>())
}

    
A Set can't go in a Bundle, so a small Saver stores it as an IntArray.

    
revealed only matters on the detail screen, so it stays there. Not everything needs hoisting.

  

  

    
A list that only builds what you see


LazyColumn {
    items(words, key = { it.id }) { word ->
        ListItem(
            headlineContent = { Text(word.term) },
            trailingContent = {
                Text(if (word.id in known) "★" else "☆")
            },
            modifier = Modifier.clickable {
                onWordClick(word)
            }
        )
    }
}

    
The list reads known but never changes it. A tap goes up as onWordClick. State goes down, events go up.

  

  

    
Two screens with type-safe routes


@Serializable object WordList
@Serializable data class WordDetail(val id: Int)

NavHost(navController, startDestination = WordList) {
    composable<WordList> { ... }
    composable<WordDetail> { entry ->
        val id = entry.toRoute<WordDetail>().id
        ...
    }
}

    
Each route is a Kotlin class. If you pass the wrong type, it won't compile. Back pops the stack with popBackStack().

  

  

    
The game part

    
    
      
  • Goal: get all 12 stars.
    • 
      
  • Rule: say it before you check. Honour system, like a card game.
    • 
      
  • Feedback: a star, the counter, and the progress bar move at once.
    • 
      
  • Levels: each word is tagged Level 1, 2 or 3, so newer members start easy.
    • 
    

    
The examples come from games the club knows: Super Mario Bros., Pac-Man, Minecraft, MakeCode Arcade, and my own Prime Smash.

Built with Android Gradle Plugin 9.4.1, Kotlin 2.4.21, Compose BOM 2026.09.00 and Navigation Compose 2.10.2. It compiles against API 37. minSdk is 24, so it installs on Android 7.0 and newer. I checked it with ./gradlew assembleDebug: it built with no errors and no warnings.

What I would change


Your stars vanish when you close the app. rememberSaveable covers rotation, not a full close. Saving for good needs DataStore or Room, which is Unit 6 of Android Basics with Compose. That is too much for this club term, but it is the first thing I'd add.


The honour system is also weak. A member can tap "I knew it" every time and get 12 stars in a minute. A real game would check the answer, maybe with 3 choices. I left that out to keep the code short enough for a starter.
