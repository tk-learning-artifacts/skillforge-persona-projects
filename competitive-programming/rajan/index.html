Know why it passed

A 4-week starter programme for a school contest team. Twelve Kattis problems, four 60-minute sessions, and one habit: before you submit, say what the judge will say.

I'm Rajan. I wrote software for a living before I taught programming to secondary students. Most new contest coders treat the judge as a slot machine. They submit, see red, change a line, and submit again. I want them to read a verdict the way an engineer reads a failing test. This is my end project for Competitive Programming Basics.

The setup // who, where, when

  • Team12 students from the school's computing club, Sec 2 and Sec 3. All can write a loop, an if and a function in Python.
  • RoomThe computer lab. One desktop each, plus the projector.
  • TimeThursdays, 3.30 to 4.30 pm. Term 3 of 2027: 8, 15, 22 and 29 July.
  • JudgeOpen Kattis, in Python 3. It is free and marks a submission in seconds.
  • GoalA team that can enter the NOI preliminary contest in February 2028 and score.

Why July and not January? The NOI preliminary is in February. A January start leaves about six weeks, and most of that goes on account set-up and nerves. Starting in Term 3 gives the team the rest of the year to practise after these four weeks.

Kattis needs users to be at least 13. Under the age of majority, a parent or guardian must accept the terms for the student. Kattis also asks for your real name. So the week before session 1, I send a consent letter home. Students make their accounts with a parent, and nobody shares a login. All my Sec 2s are 13 or older by July. That is why there are no Sec 1s in this team.

The number only measures how many people get stuck. It does not say why. So I also made sure each week adds one new idea, and the third problem of each week needs it most.

Verdict lab // predict, then check

Each card is a real mistake on one of the twelve problems. Read the code and pick the verdict Kattis would give. I use two cards at the start of each session, with the class voting by hand.

Problem: Spavanac

What does Kattis say?

Try this: before you open the answer, say which test number fails first. Kattis stops judging at the first error, so "Wrong Answer on test 2" tells you more than "Wrong Answer".

How I checked my solutions // evidence

The brief says to use problems you have solved yourself. Kattis only shows its sample tests, so a pass on the samples proves little. For each solution I did at least two of these:

  • Ran it on every Kattis sample file and compared the output exactly. All 11 problems with sample files match. Guess the Number has none.
  • Compared it with a slow, obvious version on random small inputs. I did this for Shopaholic, Tri and Perket.
  • Timed it on the biggest input the limits allow. Grid, the slowest, took about half a second for 500 by 500.
  • For Guess the Number, I wrote a small judge that plays all 1,000 secret numbers. My code never needed more than 10 guesses.

Students do the same before they submit. That is the point of the habit. The judge confirms what you already believe; it should not be the first test.

What I would change // limits

Session 1 assumes students can read input with input().split(). Two of my club members could not, last year. I tend to underrate how hard that first step is. Next time I would add a 20-minute "reading input" warm-up the week before, with Hello World and Solving for Carrots.

The set also leans on Python. NOI's main language is C++, and Python is only allowed for some tasks. Guess the Number is an interactive problem, and NOI does not allow those in Python at all. I keep it because it is the cleanest binary search I know. But a student aiming past the preliminary round will need C++ in time, and this programme does not start that.
