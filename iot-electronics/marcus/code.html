The code

Three parts: one Arduino sketch for the M5Stack Core, one secrets file and the dashboard setup. The secrets file never goes into git. It is the final version. Version 1 is described at the bottom, so you can see what changed.

01Before you start

  • Arduino IDE with the ESP32 board package from Espressif.
  • Libraries, from the Library Manager: M5Unified and Adafruit MQTT Library.
  • A free Adafruit IO account. Make it in the coach's name, not a student's. In my team, I own the account. Students use the dashboard on my laptop.
  • Three feeds: robot-volts, robot-status and pit-call. The free plan allows 10 feeds and 5 dashboards.

02secrets.h

Make this file next to the sketch. Add secrets.h to .gitignore before your first commit. The root certificate lets the board check it is really talking to Adafruit IO. Copy it from Adafruit's adafruitio_secure_esp32 example. Certificates expire, so check the example again each season.

// secrets.h: never commit this file. Never show it on a projector.
#pragma once
#define WIFI_SSID    "practice-hotspot"
#define WIFI_PASS    "a-long-hotspot-password"
#define AIO_USERNAME "your_io_username"
#define AIO_KEY      "your_io_key"   // regenerate it if it ever leaks
static const char *AIO_ROOT_CA =
  "-----BEGIN CERTIFICATE-----\n"
  "...copy from Adafruit's example...\n"
  "-----END CERTIFICATE-----\n";

03box_box.ino

// Box Box: robot battery telemetry for an M5Stack Core (ESP32).
// Sends pack volts to Adafruit IO by MQTT over TLS.
// Listens on pit-call for BOX, CLEAR, FAST and SLOW. Nothing else.
// A cloud message can change the screen and beep. It never drives the robot.
#include <M5Unified.h>
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"
#include "secrets.h"

const int      BATT_PIN = 36;      // Port B, white wire. G36 is ADC1; ADC2 is shared with Wi-Fi.
const float    DIVIDER  = 3.0;     // 20k over 10k: the pin sees a third of the pack
const float    CAL      = 1.00;    // set this after checking against a multimeter
const float    LOW_V    = 6.6;     // warn below this while running
const uint32_t NORMAL_MS = 5000;   // 12 a minute
const uint32_t FAST_MS   = 3000;   // 20 a minute
const uint32_t SLOW_MS   = 10000;  // 6 a minute
const int      OWN_BUDGET = 24;    // my own cap per minute, under Adafruit's 30

WiFiClientSecure net;
Adafruit_MQTT_Client mqtt(&net, "io.adafruit.com", 8883, AIO_USERNAME, AIO_KEY);
Adafruit_MQTT_Publish   voltsFeed(&mqtt, AIO_USERNAME "/feeds/robot-volts");
Adafruit_MQTT_Publish   statusFeed(&mqtt, AIO_USERNAME "/feeds/robot-status");
Adafruit_MQTT_Publish   pitCallGet(&mqtt, AIO_USERNAME "/feeds/pit-call/get");
Adafruit_MQTT_Subscribe pitCall(&mqtt, AIO_USERNAME "/feeds/pit-call");
Adafruit_MQTT_Subscribe throttle(&mqtt, AIO_USERNAME "/throttle");

uint32_t sendEvery = NORMAL_MS, lastSend = 0, lastScreen = 0, lastPing = 0;
uint32_t nextTry = 0, backoff = 5000, offlineSince = 0;
uint32_t sentAt[OWN_BUDGET];       // times of my last sends, for the budget
int      sentIdx = 0, missed = 0, missedOffline = 0;
float    volts = 0, vMin = 99, vMax = 0;
bool     boxCall = false, wasOnline = false;
String   note = "Booting";

float readVolts() {
  uint32_t mv = 0;
  for (int i = 0; i < 10; i++) {   // average 10 readings: smoother, a little slower
    mv += analogReadMilliVolts(BATT_PIN);
    delay(2);
  }
  return (mv / 10.0f) / 1000.0f * DIVIDER * CAL;
}

bool underBudget() {               // true if my oldest of 24 sends is over a minute old
  return sentAt[sentIdx] == 0 || millis() - sentAt[sentIdx] > 60000;
}

void handleCommand(const char *raw) {
  String c = String(raw);
  c.trim();
  c.toUpperCase();
  if (c == "BOX")        { boxCall = true;  note = "BOX BOX"; M5.Speaker.tone(2000, 400); }
  else if (c == "CLEAR") { boxCall = false; note = "Clear"; }
  else if (c == "FAST")  { sendEvery = FAST_MS; note = "FAST: every 3 s"; }
  else if (c == "SLOW")  { sendEvery = SLOW_MS; note = "SLOW: every 10 s"; }
  else                   { note = "Ignored a command"; }   // unknown text is never shown or run
}

bool ensureMqtt() {
  if (mqtt.connected()) return true;
  if (millis() < nextTry) return false;   // tries even with Wi-Fi off, so the wait keeps growing (trial 4)
  int8_t ret = mqtt.connect();     // 0 means connected
  if (ret != 0) {
    note = String("Retry in ") + (backoff / 1000) + " s";
    mqtt.disconnect();
    nextTry = millis() + backoff;
    backoff = min(backoff * 2, (uint32_t)60000);   // 5, 10, 20, 40, then 60 s
    return false;
  }
  backoff = 5000;
  note = boxCall ? "BOX BOX" : "Online";
  if (offlineSince) {              // say how long we were gone, then ask for any missed call
    String s = String("back after ") + (millis() - offlineSince) / 1000 + " s, missed " + missedOffline;
    statusFeed.publish(s.c_str());
    pitCallGet.publish("?");
    offlineSince = 0;
    missedOffline = 0;
  }
  return true;
}

void draw() {
  M5.Display.startWrite();
  M5.Display.fillScreen(boxCall ? TFT_RED : TFT_BLACK);
  M5.Display.setTextColor(TFT_WHITE, boxCall ? TFT_RED : TFT_BLACK);
  M5.Display.setTextDatum(textdatum_t::top_left);
  M5.Display.setTextSize(2);
  M5.Display.drawString(WiFi.status() == WL_CONNECTED ? "WiFi ok" : "WiFi --", 8, 8);
  M5.Display.drawString(mqtt.connected() ? "IO ok" : "IO --", 130, 8);
  M5.Display.drawString(String(sendEvery / 1000) + "s", 260, 8);
  M5.Display.setTextDatum(textdatum_t::middle_center);
  M5.Display.setTextSize(6);
  M5.Display.drawString(String(volts, 2) + "V", 160, 100);
  M5.Display.setTextSize(2);
  M5.Display.drawString("min " + String(vMin, 2) + "   max " + String(vMax, 2), 160, 160);
  String msg = note;
  if (!boxCall && volts < LOW_V) msg = "LOW: under 6.6 V";
  M5.Display.drawString(msg, 160, 200);
  M5.Display.endWrite();
}

void setup() {
  M5.begin();
  analogSetPinAttenuation(BATT_PIN, ADC_11db);   // reads about 0.15 to 3.1 V
  WiFi.mode(WIFI_STA);
  WiFi.setAutoReconnect(true);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  net.setCACert(AIO_ROOT_CA);      // TLS: check the server's certificate
  mqtt.subscribe(&pitCall);        // subscribe before the first connect
  mqtt.subscribe(&throttle);
}

void loop() {
  M5.update();
  if (M5.BtnA.wasPressed()) { vMin = 99; vMax = 0; note = "Min and max reset"; }

  bool online = ensureMqtt();
  if (wasOnline && !online && !offlineSince) offlineSince = millis();
  wasOnline = online;

  if (online) {
    Adafruit_MQTT_Subscribe *sub;
    while ((sub = mqtt.readSubscription(50))) {
      if (sub == &pitCall)  handleCommand((char *)pitCall.lastread);
      if (sub == &throttle) { sendEvery = SLOW_MS; note = "Throttled: SLOW"; }
    }
    if (millis() - lastPing > 60000) { lastPing = millis(); if (!mqtt.ping()) mqtt.disconnect(); }
  }

  if (millis() - lastScreen >= 1000) {   // the screen never waits for the cloud
    lastScreen = millis();
    volts = readVolts();
    vMin = min(vMin, volts);
    vMax = max(vMax, volts);
    draw();
  }

  if (millis() - lastSend >= sendEvery) {
    lastSend = millis();
    if (!online) { missed++; missedOffline++; }
    else if (!underBudget()) { missed++; }
    else if (voltsFeed.publish(volts, 2)) {  // 2 decimal places, in volts
      sentAt[sentIdx] = millis();
      sentIdx = (sentIdx + 1) % OWN_BUDGET;
    } else { missed++; }
  }
}

I wrote this sketch for this example. I checked it against the libraries' own examples and docs. I have not compiled it against every library version. If the compiler complains, the library examples are the place to compare.

04Walk through it

  1. Reading. The pack goes through a 20 kΩ and 10 kΩ divider. G36 sees a third of it. analogReadMilliVolts gives a calibrated reading. Ten readings are averaged. Then the multimeter check sets CAL.
  2. Screen first. The screen updates every second from the local reading. A dropped link never blanks it. The driver can always see the volts.
  3. Sending. One number, two decimal places, to robot-volts. Every 5 s normally, 12 a minute.
  4. Budget. The board keeps the times of its last 24 sends. If the oldest is under a minute old, it skips a send and counts it. Adafruit IO's free limit is 30 a minute for the whole account. This leaves room for dashboard presses.
  5. Control. pit-call takes 4 words. Anything else is ignored and never shown.
  6. Reconnect. It waits 5, 10, 20, 40, then 60 s between tries. It never stops trying, and the screen keeps working. It also tries while Wi-Fi is off, so a long drop leaves a long wait. That is the flaw behind trial 4 in the test log.
  7. After a gap. It posts how long it was gone to robot-status. Then it publishes to pit-call/get. Adafruit IO answers with the last pit call. So a BOX sent during the gap is not lost.
  8. Throttle. If Adafruit IO ever posts on /throttle, the board drops to SLOW by itself.

05The dashboard

One Adafruit IO dashboard, called Pit Wall. Five blocks:

  • Line chart on robot-volts, last hour. Y axis from 5.8 to 8.4, labelled "Pack volts (V)".
  • Gauge on robot-volts, 5.8 to 8.4, with the low mark at 6.6.
  • Text block on robot-status, so a gap note is the first thing you read.
  • Four momentary buttons on pit-call: BOX, CLEAR, FAST, SLOW. Each sends its own word.
  • Keep the dashboard private. Only the coach's laptop is signed in.

06Read the feed as JSON

Students check the last reading from a laptop with Adafruit IO's HTTP API. Send the key in the X-AIO-Key header, not in the address.

GET https://io.adafruit.com/api/v2/your_io_username/feeds/robot-volts/data/last
X-AIO-Key: (your key)

The reply is a JSON data record. Here is the part we read, with made-up values:

{
  "feed_key": "robot-volts",
  "value": "7.12",
  "created_at": "2026-10-20T09:41:05Z"
}

Look at "value". It is in quotes: a string, not a number. Adafruit IO stores values as text. Before you compare it with 6.6, turn it into a number. My students missed this twice.

07What version 1 was

Version 1 was Adafruit's ESP32 example with our feed names, plus a FAST button. It sent every 2 s, and every 1 s on FAST. Its connect function tries 3 times. Then it runs while (1); and waits for a watchdog reset. On our board the screen just froze. The test log shows what that cost us. You can run version 1 in the simulator.
