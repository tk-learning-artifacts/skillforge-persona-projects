Lights On, Nobody HomeA classroom energy monitor with two micro:bits and a Google Sheet

A micro:bit on the classroom wall listens and looks. Sometimes the room goes quiet with the lights still on. Then it plays a nudge for the last one out. Every 5 minutes, a summary goes to a Google Sheet. The class sets the nudge on or off from the Sheet.

I'm Tom. I teach sustainability through projects. My Sec 2 class asked a simple question: how long does our room sit empty with the lights on? MOE wants a two-thirds cut in the schools sector's net carbon emissions by 2030. My students wanted to know what their own room adds. We also asked who a sensor like this helps, and who it leaves out.

The brief: a mini telemetry demo. The device sends a sensor reading to the cloud and responds to a control message. Here the readings are light, sound and temperature. The control message is a mode, typed into one cell of the Sheet.

      Data-flow diagram

      Readings travel down. The mode comes back up on the right, inside the reply to each post.

      Where it breaks, hop by hop:

      • Hop 2: walls, metal cupboards and distance. Keep the node in the same room as the gateway.
      • Hop 3: someone unplugs the USB cable to charge a phone. The page says "node silent" within 3 minutes.
      • Hop 4: the PC sleeps or Chrome closes. Then nothing is sent at all. This is the weakest hop.
      • Hop 5: school network or a firewall blocks the post. Rows wait in the queue.
      • Hop 6: a wrong token. The reply says so, and the row stays in the queue until it is fixed.
      • Coming back: the mode only arrives with a reply. So a change in B1 takes up to 5 minutes.

      The code

      There are four pieces. All of them are on the code page.

      • The sensor node, in MakeCode for micro:bit V2.
      • The gateway micro:bit, in MakeCode.
      • The gateway page. It is real: plug a gateway micro:bit into a computer with Chrome and press Connect. With no micro:bit, it runs on made-up readings.
      • The Apps Script web app, behind the Sheet.

      Reliability

      We wanted a week of school days with no gaps we couldn't explain. What we did for that:

      • Every row carries the time it was measured, not the time it arrived. A row sent late still lands in the right place.
      • Rows that fail wait in a queue, saved in the browser. They go up oldest first when the network is back.
      • Each row has an id, like 2E-10:05 plus the date. The script ignores an id it has already stored. A retry never makes a double row.
      • If no reading arrives for 5 minutes, the row is still posted. It has blanks and "node silent". A gap is recorded, not hidden.
      • Chrome slows timers in a tab that has been hidden for 5 minutes. So the page builds each row when readings arrive. A backup check every 30 seconds catches a silent node. In a hidden tab it may run only once a minute. That is still in time.
      • The script uses a lock, so two posts at once can't write over each other.

      Data clarity

      A number in a cell means nothing until you know its scale. Our columns:

      ColumnWhat it means
      timeWhen the 5 minutes started, Singapore time.
      lightThe average light level, 0 to 255. The micro:bit senses light with its LED screen. It is not lux. Compare it with itself, not with a light meter.
      sound_peakThe loudest moment in 5 minutes, 0 to 255. It is not decibels. Only the micro:bit V2 has a microphone.
      temp_cThe processor chip's temperature in °C, which is close to the room. We checked it against a thermometer.
      lit_quiet_minHow many of the 5 minutes had light over 70 and sound under 80. 0 to 5.
      status"ok", "partial" or "node silent". A blank cell means no reading. A 0 always means a real 0.

      The column is called lit_quiet_min, not "wasted minutes". The Sheet cannot see people. A student reading quietly looks the same as an empty room. Fans make noise in an empty room too. So we picked thresholds from our own room. Lights on read about 110, and daylight alone about 38. An empty room with fans read about 50, and a class about 150. Those are our made-up numbers. Measure your own room first.

      Security and privacy

      • micro:bit radio is not encrypted. Anyone in range on group 83 can hear the readings and send a mode. So the node only obeys the gateway's serial number. The gateway only forwards readings from the node's serial number. That stops mix-ups between classes. It would not stop someone who really wanted to fake it.
      • Group 83, not group 0. Group 0 is the default, and every class tries it first.
      • The web app address works for anyone who has it. So each post carries a token. The script keeps the token in Script Properties, not in the code. The gateway page keeps it in that PC's browser only.
      • The script checks every value. A light of 999 or a room it doesn't know is refused.
      • The node takes only three modes: remind, quiet, test. Anything else is ignored.
      • The Control tab is a protected range. Only the eco monitors and I can change B1.
      • No personal data. Room code, light, loudness, temperature. The micro:bit turns sound into one number. Our code never records audio.
      • The web app needs anonymous access to take posts from the PC. Some school Google domains turn that off. Ask your IT team before you plan the lesson around it.

      Who it helps, who it leaves out

      Helps

      • The school's energy target. Every lit, empty hour is a small, visible cost.
      • The class. They own the data and the switch. Nobody else sets their mode.
      • Students who learn by building. Two micro:bits cost far less than a smart building system.

      Leaves out

      • The student who stays back from PE. Quiet looks empty. A nudge could leave them in a dim room.
      • The cleaner, who works with the lights on after school. The Sheet must not turn that into blame.
      • Rooms with no PC that stays on. The gateway needs Chrome on a desktop or Chromebook. It will not run on an iPad.
      • Fans. We can't tell if they are on. A fan on in an empty room is waste we never count.

      So the device never switches anything. It only nudges. And the Sheet reports a room, never a person.

      Build it

      Parts

      • Two micro:bit V2 boards. The sound sensor needs V2.
      • A battery pack with 2 AAA batteries for the node. A USB cable for the gateway.
      • A classroom PC or Chromebook that stays on, with Chrome.
      • A Google account that can make a Sheet and an Apps Script web app.
      • Removable mounting putty, and a card sign: "Energy sensor. No camera. No recording."

      Steps

      1. Make the Sheet with two tabs, Data and Control. Put the headers from the code page in Data. Put "remind" in Control!B1. Protect the Control tab.
      2. Paste the Apps Script. Add a TOKEN in Script Properties. Deploy it as a web app. Copy the address.
      3. Flash the node and the gateway micro:bits. Both use radio group 83.
      4. Open the gateway page, connect, and read each board's serial number from the log. Put them into the two programs. Flash again.
      5. Calibrate. Read the light with lights on and off. Read the sound with the room empty and full. Set LIT and QUIET between them.
      6. Put the node on the wall near the switches, at shoulder height. Leave the gateway page open. Check the first rows in the Sheet.

      Safety

      • Never open a light switch plate or touch the wiring. The node sits on the wall beside the switches, not on them.
      • Never stick anything on a fan, fan switch or socket.
      • Use putty, not tape that pulls paint, and no drilling.
      • Keep the USB cable along the desk, not across the walkway.
      • Batteries: take them out over the holidays. Never mix old and new ones.

      What I would change

      • Move the gateway off the PC. An ESP32 board could post straight to the web app. Then a sleeping PC can't stop the data.
      • Count the false alarms. We should log when someone is in the room but quiet. Then we see how often it happens.
      • Find a fair way to sense fans. A student suggested a paper strip and the micro:bit's accelerometer. It is worth a test.
      • The nudge comes after the class has left the doorway about half the time. A sensor at the door would be earlier.
