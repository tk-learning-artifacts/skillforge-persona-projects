Soft Landing: the starter

The lander, the pad and the reactions are built. The physics is missing. Students add it in 3 tasks.

Download the starter (.sb3)

What the starter has

  • All sprites, costumes and sounds. The pad moves to a random spot on each green flag.
  • The setup blocks: gravity, thrust, speed y and fuel are set. Monitors show speed y, fuel and best.
  • The flight loop, with steering and "change y by speed y" already in it.
  • The "when I receive landed" and "when I receive crashed" scripts. Nothing broadcasts them yet.
  • A Puff clone script that nothing calls. That is the stretch task.
  • A comment in the code for each task.

Press the green flag on the starter and nothing seems to happen. The lander hangs at the top. Speed y stays at 0, so "change y by speed y" moves it 0 steps every frame. I start the lesson there, with the question: what is the loop doing right now?

The Lander's code in the starter

when ⚑ clicked
set gravity to -0.05
set thrust to 0.15
set speed y to 0
set fuel to 80
switch costume to lander
say
go to x: pick random -180 to 180 y: 150
repeat until touching Pad ? or touching Ground ?
if key left arrow pressed? then
change x by -2
if key right arrow pressed? then
change x by 2
change y by speed y
when I receive landed
start sound chime
say join Landed. Fuel left: fuel
if fuel > best then
set best to fuel
when I receive crashed
switch costume to wreck
start sound crash
say join Crashed at speed round speed y

Why these tasks, in this order

  • Task 1 makes one variable change another. Students can watch the speed y monitor count down.
  • Task 2 adds a condition with "and". The fuel check is the part students forget.
  • Task 3 moves a decision outside the loop. It also connects to broadcasts that already exist.
  • Each task can be tested on its own before the next one starts.

Soft Landing: task card

Remix the starter from the class studio. Work on your own. Test after every task: click the stage, then press the green flag.

Task 1: Gravity

Click the Lander. In the repeat until loop, put this block above "change y by speed y":

repeat until touching Pad ? or touching Ground ?
change speed y by gravity
change y by speed y

Predict first. Write down what the speed y monitor will do after 1 second. Then test.

Done when: the lander falls faster and faster, and stops at the ground.

Task 2: Thrust

Under your gravity block, add an if block. Use "and" from Operators:

change speed y by gravity
if key up arrow pressed? and fuel > 0 then
change speed y by thrust
change fuel by -1

Hint: "key up arrow pressed?" is in Sensing. Drag the orange "thrust" variable into "change speed y by".

Done when: the up arrow slows the fall, and fuel stops at 0.

Task 3: The verdict

After the repeat until loop, not inside it, add this if-else:

if touching Pad ? and speed y > -2 then
broadcast landed
else
broadcast crashed

Why outside? Inside the loop it would run every frame. You want it once, at touchdown.

Done when: a slow landing chimes and a fast one crashes.

Stretch: Exhaust and a better crash

Add "create clone of Puff" inside your thrust if block:

if key up arrow pressed? and fuel > 0 then
change speed y by thrust
change fuel by -1
create clone of Puff

Then: miss the pad gently and read the crash bubble. Make it say "Missed the pad" instead.

I tested the card on a colleague

The colleague and the timings are made up, like me.

A physics teacher tried the starter in the lab. She has used Scratch twice. I said nothing until she finished.

  • Task 1 took 6 minutes. I had guessed 2. She looked for gravity in the Motion blocks first. I added the picture of the block to the card.
  • Her first gravity block went below "change y by speed y". It still worked. She asked whether the order matters. It does, a little. The lander moves one frame later. That became a discussion question in the lesson.
  • Task 2 took 10 minutes. She left out "fuel > 0" and flew forever. The card's "done when" line now checks that fuel stops at 0.
  • Task 3 took 8 minutes. She put the if-else inside the loop. While flying, the lander is not on the pad. So it broadcast "crashed" every frame from the very first frame. I added the "Why outside?" line.

I underrated task 1. A student who has never seen a variable change another variable needs time there. In the lesson I now demo it first.
