Scam or Not?

A 3-page website for my Sec 2 class. It teaches 4 signs of a scam, tests them with a 6-message quiz, and says where to get help in Singapore.

I'm Daniel. I have been a trainer for six months, and I learn alongside my classes. I teach a Sec 2 coding class. This term our school asked us to link one unit to cyber wellness. Scams felt like the topic my students would care about most. So I built the site I wanted to show them, and then turned it into their starter.

My class and colleague are made up, like me. The site, the facts on it and the WAVE fixes are real. Every scam message on the site is made up.

1. The live site

Live link tk-learning-artifacts.github.io/skillforge-persona-projects/web-foundations/daniel/site/

It is published free with GitHub Pages. Try it on your phone first, because that is where my students will open it. The three pages:

  • Spot the signs
    The 4 signs as cards, the ACT reminder, and two numbers from the police.
  • Scam or not?
    The JavaScript feature. Six made-up messages. Pick Scam or Looks safe, and get a clue each time.
  • Get help
    What to do if a message worries you, the 1799 helpline, and what to do if you already paid.

How it meets the brief

  • At least 2 linked pages: there are 3. The same header nav is on each page, and the current page is marked with aria-current="page".
  • A flexbox layout that works on phones: the sign cards and the ACT cards sit in a row with display: flex. A media query at 600 px switches them to flex-direction: column, and wraps the nav. I did it the way the module's card layout task teaches, so my students see the same pattern.
  • 1 JavaScript feature: the quiz. It finds the messages with querySelectorAll, adds two buttons to each, and listens with addEventListener. It writes the clue and the score with textContent. The score line uses aria-live, so a screen reader reads out each new score.

Three things that confused me

  • I assumed CodePen was fine for school. Its terms say its services are not for anyone under 18. My students use GitHub instead, which allows 13 and over.
  • My quiz checked data-answer="true" against true and never matched. dataset values are always strings. Now I use the words "scam" and "safe".
  • I thought scams were mostly an older people's problem. The police's 2024 numbers say 70.9% of victims were under 50. That fact went on the home page.

What I fixed

  1. Missing alternative text (4). The four sign icons had no alt. Each card's heading already says the sign, so the icons now have alt="". Helps screen reader users, who no longer hear four file names.
  2. Linked image missing alternative text (2). The logo was an image link with no words. The link now holds the words "Scam or Not?", and the icon is hidden from screen readers. Helps screen reader users know the link goes home.
  3. Broken skip link (2). My skip link pointed to #content, but the main tag had id="main". One typo, on every page. It now points to #main. Helps keyboard users jump past the nav.
  4. Missing form label (6). The draft quiz used radio buttons with the words Scam and Safe beside them, not tied to them. I swapped them for two real buttons per message, which need no label. Each answer now gets its clue straight away, not after a Check button. Helps screen reader users, and anyone tapping on a small phone screen.
  5. Empty button (1). The Start again button was only a circular arrow icon. It now says "Start again". Helps everyone. Two colleagues guessed it meant refresh the page.
  6. Very low contrast (9). My pale grey captions and timestamps were 2.3 to 1 on white. White text on my mint button was 1.67 to 1. WAVE wants 4.5 to 1. Captions now use dark grey at 9.14 to 1. The button is deep green with white text at 6.42 to 1. I checked the dark mode colours too. Helps students with low vision, and anyone reading in sunlight.

Keyboard-only test

  • The first Tab shows the skip link. Enter jumps to the main content.
  • Tab reaches each Scam and Looks safe button in order. Space or Enter picks one.
  • After an answer, both buttons are disabled, so Tab moves on to the next message.
  • Start again moves focus back to the first message, so you don't have to tab back up.
  • The 1799 number is a phone link, so it can be tapped or reached with Tab.

3. Starter project and task card

Students build their own Scam or not? page. The starter has 2 message cards and 3 TODOs: a third card in HTML, the flexbox layout in CSS, and the answer check in JavaScript. They copy it from a GitHub template repository, edit it in github.dev and publish it on GitHub Pages.

  • The task card
    One A4 page with a hint per TODO, a bug checklist, 3 extensions and publishing rules.

Rubric check

  • Site works on phone and laptop: checked at 360 px and 1200 px, in light and dark mode. No sideways scrolling. Every button is at least 44 px tall.
  • Uses semantic HTML throughout: header, nav, main and footer on every page. Signs and steps are lists. The quiz messages are an ordered list, and each set of buttons is a labelled group.
  • No WAVE errors left: 0 errors and 0 contrast errors on all 3 pages, by WAVE's rules. Please run WAVE on the live links to confirm.
  • Starter tasks fit your students' level: TODO 1 everyone can do, TODO 2 adds one new idea, TODO 3 is a short if and else. My colleague test changed the task card twice.

What I'd change

The quiz has 4 scams and 2 safe messages. A student who presses Scam every time scores 4 out of 6. I only noticed when I tried to break my own quiz. Next time I'd balance it, 3 and 3, and shuffle the order.

github.dev has no preview, so each change means commit, wait and refresh. That slow loop hurts beginners most. I'd also like a way to publish that doesn't put a student's GitHub username in the web address. Some students pick usernames close to their real names.
