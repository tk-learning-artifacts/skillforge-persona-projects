Starter: build your own Scam or not? page

A half-made quiz page with 2 message cards. Students add a third card, lay the cards out with flexbox, and write the code that checks each answer. Then they publish it.

  • Run the starter as it is

How students get it

I put the 3 files in a GitHub repository and turned on the Template repository setting. Each student then makes their own copy.

  1. Open my template repository. Above the file list, click Use this template, then Create a new repository.
  2. Name it scam-or-not. Choose Public, because GitHub Pages on a free account needs a public repository.
  3. Press the full stop key on the repository page. This opens github.dev, a code editor in the browser.
  4. Edit the files, then commit the changes from the Source Control panel.
  5. In Settings, then Pages, publish from the main branch. The site appears at username.github.io/scam-or-not/.

What I got wrong first

I planned to use CodePen, so students could fork a starter pen. Then I read CodePen's terms. Its services are not for anyone under 18. My Sec 2 students are 13 or 14. GitHub's terms say 13 or older, so GitHub works. I still checked with our school's ICT team before students made accounts.

github.dev has one catch. It cannot run code, so there is no preview. Students commit, then refresh their Pages link. GitHub says a change can take up to 10 minutes to show. In my test it was usually quicker, but I plan for the wait.

How I run it: one 60-minute lesson

32 Sec 2 students on school Chromebooks. They made GitHub accounts in an earlier lesson.

  1. 0 to 5 min. Settle and sign in to GitHub.
  2. 5 to 15 min. Pairs play the Scam or not? quiz. Then we list the 4 signs on the board.
  3. 15 to 20 min. I demo Use this template and the full stop key, live.
  4. 20 to 25 min. Everyone turns on GitHub Pages now, so the first publish runs while they code.
  5. 25 to 50 min. TODOs 1, 2 and 3, with the task card. I walk round with the "check these first" list.
  6. 50 to 57 min. Swap links with a partner. Play each other's quiz on a phone.
  7. 57 to 60 min. Exit ticket: which TODO was hardest, and why?

Check: 5 + 10 + 5 + 5 + 25 + 7 + 3 = 60 minutes.

Why these TODOs fit Sec 2

  • TODO 1 is copy and change. Everyone can finish it, and it shows how the HTML is built.
  • TODO 2 needs one new idea: a media query. The task card gives the shape of it.
  • TODO 3 is the stretch for most of the class. The loop and the click listener are written. Students write only the if and else.
  • Fast finishers get 3 extensions on the task card, ending with a WAVE check on their own live link.

Test run with a colleague

My colleague is made up, like me.

  • She finished in 18 minutes. Students will take longer, so 25 minutes is tight. Extensions can go home.
  • Her first commit did not show for about 2 minutes. She thought she had broken it. I added "wait, then refresh" to the task card.
  • In my first draft, cards had data-answer="true" and I compared it with true. It never matched. Values from dataset are always strings. Now both sides are words, "scam" or "safe".
